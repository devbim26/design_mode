# Многопользовательский режим «users» — руководство

Одна установка DevBIM Image Studio на ПК владельца + публичный адрес
(туннель) = много пользователей с личным входом, личным ключом
ImageRouter и изолированными рабочими файлами.

- Спека/план: `docs/superpowers/specs|plans/2026-10-07-multiuser-users-mode*`
- Технический контекст: `HANDOFF.md`, раздел «Многопользовательский режим»
- Тесты: `tests/test_userauth_*.py`

---

## 1. Как это устроено (одним абзацем)

Каждый пользователь заходит по публичному адресу и видит страницу входа
с полями «Почта», «Пароль» и «Токен ImageRouter». Аккаунт создаёт
владелец (вы). Ключ ImageRouter вы тоже выдаёте лично: заводите его на
imagerouter.io и передаёте человеку вместе с паролем. Пользователь вводит
ключ один раз при первом входе — сервер проверяет его и запоминает; после
этого вход только по почте и паролю. Всё, что человек создаёт (картинки,
борды, очереди, IFC/PDF/3D-файлы), привязано к нему: чужого он не видит,
его файлы лежат в его папке `data/<вид>/<почта>/`.

## 2. Включение / выключение режима

Режим задаётся в `.env` корня проекта (у основного экземпляра **уже
включён**):

```env
STUDIO_AUTH_MODE=users
STUDIO_SESSION_SECRET=<сгенерирован setup_site_auth.py, не трогать>
SITE_PASSWORD=<пароль владельца-администратора>
```

После смены режима — перезапуск: `launch\_restart_server.ps1`.
Другие режимы сохранены: `password` (один общий пароль; компании) и
`sso` (вход по JWT с devbim.com). Компаниям режим не менялся — у каждой
свой `companies/<код>/.env`.

## 3. Быстрый старт владельца

1. Запустите систему: `launch\start-system-design.bat` (сервер + туннель).
2. Откройте адрес (локально `http://localhost:9090`, публичный —
   `https://design.dev-bim.com`).
3. Войдите как администратор: поле «Почта» оставьте **пустым**, в
   «Пароль» введите `SITE_PASSWORD` из `.env`. В баннере появится
   `admin@local · admin`.
4. Создайте пользователя: `/admin` → форма «Создать пользователя»
   (почта, имя, пароль от 8 символов, роль, токен ImageRouter) — или из
   консоли:
   ```
   python user_manager.py add ivan@mail.ru --name Иван
   ```
   без `--password` пароль сгенерируется и напечатается.
5. Выдайте человеку: пароль + его персональный ключ ImageRouter
   (создаёте на imagerouter.io). Пользователь вводит ключ в окне входа
   при первом входе (или вы зададите его сразу в форме/через
   `set-token` — тогда поле токена можно не заполнять).

## 4. Вход пользователей

| Ситуация | Что делать |
|---|---|
| Первый вход | Почта + пароль + токен ImageRouter (три поля) |
| Обычный вход | Почта + пароль (токен уже сохранён на сервере) |
| Смена токена (перевыпустили ключ) | Ввести новый токен в поле при входе — он проверится и перезапишется. Или задать через `/admin` → «Токен…» |
| Забыл пароль | Сообщает вам; `/admin` → «Пароль…» или `python user_manager.py set-password ivan@mail.ru` |
| Заблокирован («Учётная запись заблокирована») | Вы нажали «Заблокировать» в `/admin` (или `revoke`) — разблокировать там же |
| Владелец-администратор | Пустая почта + `SITE_PASSWORD` |

Токен при вводе проверяется запросом к `api.imagerouter.io/v1/auth/test`:
неверный ключ — вход не пройдёт с пояснением; при недоступности ImageRouter
токен принимается с предупреждением в лог (чтобы не запирать человека).

## 5. Токены ImageRouter — правила

- Хранятся на сервере (`data/data/studio.sqlite`), в браузер не уходят;
  в интерфейсе видно только «есть/нет» и последние 4 символа
  (`/api/v1/imagerouter/status`).
- Все облачные вызовы пользователя идут с его ключом: генерация и правки
  на канвасе, апскейл, Prompt Assistant, «Ask AI», 3D-аналитик, баланс
  кредитов, облачные ноды Workflows.
- **У пользователя без токена глобальный ключ НЕ подставляется** —
  генерация возвращает «Персональный токен ImageRouter не задан —
  обратитесь к администратору». Ваши кредиты чужими запросами не тратятся.
- Вы (вход по SITE_PASSWORD) и аккаунты с ролью admin без своего токена
  работают на глобальном ключе `IMAGEROUTER_API_KEY` из `.env`.
- Убрать токен: `/admin` → «Токен…» → пусто, или
  `python user_manager.py set-token ivan@mail.ru -`.

## 6. Управление пользователями

### Панель `/admin` (роль admin)

Таблица: почта, имя, роль, наличие токена, количество объектов
(картинки/борды/IFC/PDF/3D), последний вход. По строке: выбор роли
(override), «Пароль…», «Токен…», «Заблокировать/Разблокировать». Сверху —
форма создания. Роль и блокировка применяются мгновенно (на каждом
запросе), перезапуск не нужен.

### CLI `user_manager.py` (в корне проекта)

| Команда | Действие |
|---|---|
| `add <email> [--name Имя] [--role user\|admin] [--password …] [--token sk-…]` | Создать (без `--password` — сгенерировать и напечатать) |
| `list` | Список: почта, роль, токен?, блокировка |
| `set-password <email> [--password …]` | Смена пароля |
| `set-token <email> <token \| ->` | Задать / очистить токен |
| `role <email> user\|admin` | Роль-override |
| `revoke <email>` / `restore <email>` | Блокировка / разблокировка |
| `--root <путь>` | Работа с другим INVOKEAI_ROOT (например, компанией) |

Удаления пользователей нет сознательно: отзыв доступа — `revoke`,
файлы остаются (бэкап/разборки) — папку `data/<вид>/<почта>/` можно
удалить руками.

## 7. Кто что видит (изоляция)

| Данные | Где лежат | Кто видит |
|---|---|---|
| Картинки, борды, очереди | общая галерея InvokeAI + карта владения | только свои; админ — всё |
| IFC-модели | `data/ifc/<почта>/…` (свои загрузки и 3D-результаты) | только свои; админ — все папки + корень |
| PDF | `data/pdf/<почта>/…` | только свои; админ — все |
| Легаси-файлы (до режима users, в корнях `data/ifc`, `data/pdf`) | корень | админ и владелец по тегу |
| Style-пресеты и Workflows | общие | чтение — все, запись — только admin |
| Массовые операции очереди, удаление «без категории» | — | только admin |
| WebSocket-события | комнаты `user:<id>` | только свои события генерации |

Админ (`admin-local` и аккаунты с ролью admin) не фильтруется: видит все
файлы (в списках IFC/PDF у каждого файла указан `owner` — почта),
картинки и очереди. При совпадении имён файлов в разных папках админ
видит оба экземпляра; открытие/удаление берёт файл из корня, затем из
подпапок по алфавиту.

## 8. Роли

- `user` — обычный пользователь: генерация на своём ключе, свои файлы.
- `admin` — то же + всё управление; без своего токена — глобальный ключ.
- `admin-local` — вы (вход по SITE_PASSWORD): всегда admin, глобальный ключ.

## 9. Безопасность

- Пароли — только хэши PBKDF2 (240k итераций); при неверном вводе —
  пауза 0.3 с; сессия — подписанная HMAC-кука (HttpOnly, SameSite=Lax),
  срок `STUDIO_SESSION_TTL` (по умолчанию 12 ч).
- Флаг `Secure` у куки убран сознательно: туннель может терминироваться
  в http, иначе кука не придёт. Для https-адреса это ничего не ухудшает.
- Отзыв (`revoke`) и смена роли действуют мгновенно на следующем запросе.
- `SITE_VALID_UNTIL` (срок лицензии) действует как и раньше: после даты
  сервис закрывается страницей «Лицензия истекла» для всех.
- Подмена заголовка `x-studio-user` снаружи вырезается мидлварью.

## 10. Частые проблемы

| Симптом | Причина / решение |
|---|---|
| «Персональный токен ImageRouter не задан» при генерации | У пользователя нет токена — задайте в `/admin` («Токен…») или пусть введёт при входе |
| «Токен ImageRouter отклонён» на входе | Неверный/отозванный ключ — выдайте новый |
| «Сервер не настроен: STUDIO_SESSION_SECRET» | Пустой секрет в `.env` — запустите `setup_site_auth.py` (сгенерирует) и перезапустите сервер |
| «Менеджер моделей»/кредиты дают 401 у пользователя | Нет токена — это ожидаемо (эти разделы требуют ключ) |
| 3D-задача «не найдена» после перезапуска сервера | Статусы задач живут в памяти; сам IFC-файл сохранён во вкладке IFC |
| Пользователь не видит старые файлы | Легаси-файлы корня без владельца видит только админ; перезалейте или скопируйте в папку пользователя |
| Забыли SITE_PASSWORD | Он в `.env` корня (строка `SITE_PASSWORD=`) |

## 11. Включить режим users у компании (по желанию)

1. В `companies/<код>/.env`: `STUDIO_AUTH_MODE=users` + добавить
   `STUDIO_SESSION_SECRET=<случайная строка>` (или запустить
   `setup_site_auth.py`, сгенерирует сам).
2. Перезапустить экземпляр компании (`stop_company.py` + `start_company.bat`).
3. Создавать пользователей: `python user_manager.py add <email> --root companies/<код>/data`.
