# План: 3D Design слит не тот источник (холст) — фикс stale-картинки

Дата: 2026-09-20 · Ветка: `3d` · Тип: багфикс (systematic-debugging, корень доказан)

## Симптом

Пользователь кладёт референс-фото на холст, жмёт «3D Design» → Generate,
получает IFC «совсем другого дома». Впечатление: «уходит какое-то дефолтное
сообщение».

## Корневая причина (доказана E2E 20.09)

Сервер и VLM НЕ при чём: прямой пробник `_call_vlm(SYSTEM_FACADE)` с фото
особого дома вернул сцену, точно совпадающую с фото (цвет стен #bdb18a,
2 этажа, 3 окна в ряд). Баг — во фронте `devbim_topright_buttons.js`:

1. `canvasComposite()` не защищён от исключений. Если Konva-стейдж
   существует, но оторван от DOM / 0×0 (панель канваса не смонтирована:
   вкладка Generate при открытии модалки, dockview-панель не аттачится),
   `stage.toCanvas({width:0,height:0})` кидает `InvalidStateError` (drawImage
   на canvas 0×0).
2. Исключение обрывает `refresh3DSource()` на середине: превью
   затирается (`img.src=''` успевает выполниться), бейдж остаётся «—», но
   `S3.image` НЕ сбрасывается — в нём КАРТИНКА ПРОШЛОГО открытия модалки
   (фолбэк галереи из первого раза).
3. `run3D()` шлёт `S3.image` → POST несёт старую галерейную картинку при
   ПУСТОМ превью. E2E-доказательство: байты POST ==
   `data/outputs/images/08521737-….png` (выбранная вчера в галерее),
   ≠ фото, лежащему на холсте.

Дополнительный путь: открытие модалки на вкладке без менеджера канваса →
`canvasComposite() → null` → тихий фолбэк `viewerImage()` (последняя
выбранная в галерее) с бейджем «Галерея» — замысел, но в паре с (2)
становится ловушкой.

## Задачи

1. **`imagerouter/devbim_topright_buttons.js`**
   - `canvasComposite()`: всё тело в try/catch → любой сбой = `null`;
     гвард `width()/height() > 0` до рендера.
   - `refresh3DSource()`: `S3.image = null` ДО попытки композита;
     try/catch вокруг вызова. Инвариант: превью/бейдж/POST всегда из
     одного `S3.image`, «стоечного» состояния больше нет.
2. **`threed/threed_router.py`** — диагностика: дамп `_threed_last.json`
   дополняется `image {bytes, sha1, w, h}` (что реально ушло в VLM;
   sha1 сравнивается с файлами галереи/холста) и `vlm_head` (голова
   сырого ответа VLM, 300 символов).
3. Деплой: `setup_imagerouter.py` + `setup_threed.py` + рестарт
   `_restart_server.ps1`; порядок и проверки — по HANDOFF.

## Проверка

- E2E-репродукция (Playwright, `data/probe/_e2e_canvas_ref.py`):
  после фикса POST-картинка == превью модалки (по длине dataURL),
  при недоступном композите — честный бейдж «Галерея»/«—», никаких
  скрытых отправок старого.
- `tests/test_threed.py` — без регрессий (после `setup_threed.py`).
- Живая генерация не требуется (серверная часть не меняла поведения).

## Не в scope

- Почему dockview-панель канваса не аттачится в свежем профиле браузера
  (окружение тестов; у пользователей с сохранённой раскладкой канвас
  монтируется). Фикс делает деградацию безопасной в любом случае.
