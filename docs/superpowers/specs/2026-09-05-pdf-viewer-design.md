# Спека: PDF-вьювер — вкладка «PDF» (DevBIM / InvokeAI 6.2.0)

Дата: 05.09.2026. Ветка: `feature/pdf-viewer` (от `feature/ifc-viewer`).

## Цель

Просмотр PDF-документов в DevBIM Studio: загрузить документ (с диска или
с сервера), найти нужную страницу, выделить фрагмент рамкой и отправить
его картинкой **на холст** (подложка для генерации) или **в ассеты**
(галерея InvokeAI). Итог работы — картинки для последующей работы.

## Принятые решения (пользователь не ответил на уточняющие вопросы — выбраны рекомендованные варианты)

- **Размещение**: отдельная вкладка «PDF» в левой рейке после «IFC»
  (как вкладка IFC). Embed-панель на холсте НЕ делается (YAGNI, меньше
  патчей dockview; при необходимости добавляется позже по образцу `IFCE`).
- **Рамка**: одна за раз; новая рамка заменяет предыдущую; ESC — сброс.
- **«На холст»**: переиспользуется существующий мост
  `window.__devbimIfc.toCanvas(dto, false)` из `setup_ifcviewer.py`
  (поведение кнопки «Редактировать»: растровая подложка + выделенный слой
  «Маска перерисовки» + кисть). Мост фокусирует холст — пользователь
  автоматически переключается на вкладку «Холст». ГРАБЛЯ (найдена при
  проверке): мост читает `window.__devbimIfcCtx`, который выставляет
  только панель IFCV на холсте — с вкладки PDF он был null. Решение:
  компонент `PDFE` сам захватывает `Je()` (store) в `__devbimIfcCtx`
  при монтировании вкладки PDF (вкладки pdf/canvas не активны
  одновременно, за глобаль не спорят; JS_PDF_PANEL_V2 + миграция V1→V2).
- **«В ассеты»**: только загрузка в галерею (`POST /api/v1/images/upload`
  с `image_category=user`) — вкладка «Assets» галереи фильтрует
  `categories=control|mask|user|other`; `general` попал бы в
  «Изображения» (находка при проверке). «На холст» грузит с
  `general` — проверенный путь IFC-снимков.
- **Рендеринг**: PDF.js 5.4.149 (main + worker) хранится локально в
  `pdf/assets/` → деплой в `dist/pdf/` — офлайн, без CDN (как web-ifc у IFC).
- **Хранение документов на сервере**: `<INVOKEAI_ROOT>/pdf`
  (per-company автоматически через `get_config().root_path`), только `.pdf`,
  лимит 500 МБ — симметрично IFC.
- **Автовосстановление**: переключение вкладок размонтирует iframe (как у
  IFC), поэтому последний серверный документ + номер страницы пишутся в
  localStorage (`devbim:pdf:lastDoc`, `devbim:pdf:lastPage`) и
  восстанавливаются при открытии вкладки. Локальные (с диска) файлы не
  восстанавливаются.

## Компоненты

1. **`pdf/pdf_router.py`** → деплой в `venv/.../routers/pdf.py`, монтируется
   под `/api` (копия паттерна `ifc_router.py`):
   - `GET /api/v1/pdf/list` — список документов;
   - `POST /api/v1/pdf/upload` — multipart-загрузка (только `.pdf`, ≤500 МБ);
   - `GET /api/v1/pdf/file/{name}` — скачать;
   - `DELETE /api/v1/pdf/file/{name}` — удалить.
2. **`pdf/pdfviewer.html`** — standalone-страница в iframe (стилистика
   ifcviewer.html: тёмная тема, акцент #38BDF8, водяной знак DevBIM).
3. **`setup_pdfviewer.py`** — идемпотентный установщик: деплой файлов,
   патчи `api_app.py` и собранных JS-бандлов (бэкапы `*.pdfviewer-bak`).
4. **`tests/test_pdf_router.py`** — plain asserts (имена/пути/лимиты).

## UI вьювера

- **Header**: логотип «PDF**Viewer**», «Открыть файл…» (диск),
  «⬆ На сервер» (загрузить текущий документ на сервер; скрыт, если документ
  уже с сервера), select «— с сервера —» + ↻, chip-статус (имя · N стр.).
- **Сайдбар слева** с двумя секциями: «Страницы» — сетка миниатюр
  (ленивый рендер через IntersectionObserver, ширина ~110px, клик —
  переход, текущая подсвечена) и «Оглавление» — дерево `getOutline()`
  (скрыто, если в PDF нет оглавления).
- **Вьюпорт**: страница по центру на тёмном фоне; плавающий тулбар
  слева сверху: зум −/+, «Вписать», «100%», поворот ↻; панель навигации:
  «‹ [N] / M ›» (input + стрелки). Скролл — колесо/скроллбар,
  Ctrl+колесо — зум.
- **Рамка**: drag ЛКМ по странице — прямоугольник (акцент, полупрозрачная
  заливка, затемнение вне рамки), при рисовании показывается размер.
  Минимальный размер 8×8 CSS-px, иначе клик-сброс. ESC — сброс. Зум/
  поворот/смена страницы сбрасывают рамку.
- **Action bar** (плавающая, внизу по центру, видна при наличии рамки):
  размер фрагмента на выходе, «🖼 На холст», «💾 В ассеты». Кнопки
  блокируются на время операции, статус — в футере/тосте.
- **Footer**: статус (страница, зум, имя файла, ошибки), как у IFC.
- CSS-хук `body.embed` (?embed=1) сохранён на будущее.

## Конвейер фрагмента

1. Рамка хранится в CSS-px отображаемого канваса.
2. Offscreen-рендер всей страницы в масштабе `S = clamp(2048 / max(w,h), displayScale, 6)`;
   если площадь полного рендера > 16 Мп — `S` уменьшается (лимит канваса
   браузера). Белый фон (прозрачность PDF).
3. Кроп `(x·S, y·S, w·S, h·S)` → `canvas.toBlob('image/png')`.
4. `POST /api/v1/images/upload?image_category=<general|user>&is_intermediate=false`
   (multipart, имя `pdf-p<N>.png`) → ImageDTO.
5. «На холст»: `window.parent.__devbimIfc.toCanvas(dto, false)` (категория
   `general`). «В ассеты»: категория `user`, тост «Сохранено во вкладке
   „Assets“ галереи».

## Патчи бандлов (анкеры — строки ПОСЛЕ setup_ifcviewer.py)

- `api_app.py`: импорт `pdf` + `app.include_router(pdf.pdf_router, prefix="/api")`
  после строки ifc-роутера.
- App-бандл (3 замены + вставка):
  - навбар: `o.jsx(Ad,{tab:"ifc",icon:o.jsx(RA,{}),label:"IFC"})` →
    `...,o.jsx(Ad,{tab:"pdf",icon:o.jsx(vx,{}),label:"PDF"})` (`vx` — иконка
    «документ», function-декларация в той же области видимости);
  - TabContent: `e==="ifc"&&o.jsx(IFE,{})` → `... ,e==="pdf"&&o.jsx(PDFE,{})`;
  - компонент `PDFE` (iframe `/pdfviewer.html`, `Fe.unregisterTab("pdf")`,
    обёртка `yf`) перед `const cue=u.memo(` — рядом с `IFE`; кроме того,
    `PDFE` захватывает `Je()` в `window.__devbimIfcCtx` (см. «На холст»
    выше) — без этого мост с вкладки PDF не работает;
  - гейт: если в App-бандле нет `__devbimIfc` — ошибка установки
    «сначала запустите setup_ifcviewer.py» (мост «На холст» общий).
- index-бандл: enum activeTab `..."queue","ifc"])` → `+ "pdf"`.

Порядок после `pip install --force-reinstall`:
rebrand → imagerouter → ifcviewer → **pdfviewer** → siteauth.

## Обработка ошибок

- Повреждённый/нечитаемый PDF — красный статус в футере.
- Пароль: `onPassword` → `prompt()` (3 попытки, далее ошибка).
- 413/400 от `/upload` — текст в футере/тосте.
- Мост недоступен (`__devbimIfc` нет) — понятная ошибка в тосте.
