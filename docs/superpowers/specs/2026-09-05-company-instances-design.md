# Дизайн: Мультикомпанность — отдельный экземпляр сервера на компанию (Вариант B)

Дата: 2026-09-05. Статус: согласован с пользователем.

## Контекст

Сервис DevBIM Image Studio (локальный InvokeAI 6.2.0 + ребрендинг + ImageRouter
+ IFC-вьювер, см. HANDOFF.md) продаётся по лицензиям компаниям. Сейчас:
- один сервер на порту 9090, вход по одному общему паролю
  (`SiteAuthMiddleware`, `SITE_PASSWORD` из `.env`);
- галерея сгенерированных картинок и IFC-файлы общие для всех пользователей
  (хранилище InvokeAI в `data/`);
- генерация выполняется в облаке ImageRouter — локальный сервер только
  посредник, CPU-нагрузка минимальна.

Требования пользователя:
1. Пользователи группируются по компаниям-лицензиатам; вход по одному
   паролю на компанию («дал пароль — компания зашла»).
2. Рабочие файлы компаний изолированы друг от друга.
3. Пользователи скачивают результаты себе на компьютер; будущее
   расширение — общее пространство внутри компании (вне скоупа).

Выбран **Вариант B: отдельный экземпляр сервера на компанию** — изоляция
данных получается автоматически (разные процессы, разные корни), вход
остаётся простым паролем, хрупких патчей API не требуется.

## Архитектура

Один общий патченный venv (патчи ребрендинга/imagerouter/ifcviewer/siteauth
применяются к `site-packages` один раз и разделяются всеми экземплярами).
Каждая компания — отдельный процесс InvokeAI со своим корнем и портом:

```
InvokeAI/                      # общий venv + скрипты патчей
├── venv/                      # один на все компании
├── companies/                 # корневые каталоги компаний
│   ├── stroyproekt/           #   корень InvokeAI (--root)
│   │   ├── .env               #   SITE_PASSWORD, IMAGEROUTER_API_KEY,
│   │   │                      #   ADMIN_PASSWORD, SITE_VALID_UNTIL
│   │   ├── invokeai.yaml      #   порт, host
│   │   └── (data/, databases/ — создаёт InvokeAI при старте)
│   └── <код-компании>/
├── companies.json             # реестр: код, имя, порт, даты, статус
├── create_company.py          # создать экземпляр компании
├── list_companies.py          # список + статус (порт слушает?)
├── start_company.bat          # start_company.bat <код>
└── stop_company.py            # остановка процесса по порту
```

- Порты: 9100+ (9090 остаётся за «внутренним» экземпляром).
- `.env` компании грузится существующим `_load_env_file` (cwd → INVOKEAI_ROOT
  → на уровень выше): батник запускает сервер с `cwd=companies/<код>` и
  `INVOKEAI_ROOT=companies/<код>`.
- Ключ ImageRouter: пока один общий (копируется из основного `.env`);
  при желании — отдельный ключ на компанию в её `.env` (изменение —
  редактирование одной строки, перезапуск не нужен, `_load_key` читает env).

## Компоненты

### 1. `create_company.py`

```
python create_company.py --name "ООО «Стройпроект»" --code stroyproekt \
       [--valid-until 2027-09-05] [--password <пароль>]
```

- Валидация кода: `[a-z0-9-]{2,32}`, уникальность.
- Пароль: сгенерировать читаемый (слова/группы цифр), вывести в консоль
  и сохранить заметку `companies/<код>/CREDENTIALS.txt` (напоминание:
  выдать компании, файл не в git).
- Свободный порт: min(занятые в companies.json) + 1, начиная с 9100.
- Генерирует: каталог, `.env`, `invokeai.yaml` (копия конфига базового
  экземпляра с заменой порта), записывает запись в `companies.json`.
- Первый запуск экземпляра выполняет инициализацию корня (InvokeAI создаёт
  структуру); можно оставить пользователю `start_company.bat <код>`.

### 2. Скрипты управления

- `start_company.bat <код>` — установка cwd/INVOKEAI_ROOT на каталог
  компании, запуск `invoke-web --root ...` тем же venv (по образцу
  `start_devbim.bat`, PYTHONUTF8=1).
- `stop_company.py <код>` — найти процесс, слушающий порт компании
  (psutil), завершить.
- `list_companies.py` — таблица: код, имя, порт, срок лицензии,
  запущен/нет.

### 3. Срок лицензии (расширение `site_auth.py`)

Мидлварь читает из `.env` необязательный `SITE_VALID_UNTIL=ГГГГ-ММ-ДД`.
Если дата прошла — форма входа заменяется страницей «Срок лицензии истёк,
свяжитесь с devBIM» (контакты), уже выданные куки считаются невалидными
(добавить дату в токен: sha256(соль+пароль+дата) достаточно — смена даты
инвалидирует куки). Продление — правка `.env`, перезапуск не нужен.

### 4. Админ-функции (существующие, без изменений)

Админский пароль менеджера моделей (`ADMIN_PASSWORD`) — у каждой компании
свой в её `.env`. IFC-хранилище и галерея — в корне компании, изолированы
автоматически.

## Ошибки и edge-cases

- Порт занят (старт вручную после сбоя) — `create_company.py` выбирает
  свободный; `start_company.bat` при ошибке bind пишет в лог компании
  `companies/<код>/server.log`.
- Смена пароля компании — правка `.env` (куки инвалидируются мгновенно,
  перезапуск не нужен — текущее поведение `_site_password`).
- Отзыв лицензии немедленно: `stop_company.py` + смена пароля; мягко:
  `SITE_VALID_UNTIL` в прошлое.
- Обновление InvokeAI (`pip install --force-reinstall`) требует повторного
  применения патчей (rebrand → imagerouter → ifcviewer → siteauth) — один
  раз на все компании (общий venv). Проверка парса бандлов — по HANDOFF.md.
- Память: один простой экземпляр ~0.5–1 ГБ ОЗУ. До ~5–10 компаний на
  одной машине приемлемо; дальше — пересмотр (вариант A или второй сервер).

## Что НЕ делаем сейчас (задел на будущее)

- Общее пространство файлов внутри компании (галерея уже общая внутри
  экземпляра — по сути это уже «Б» из обсуждения; отдельный экспорт/импорт
  промптов не нужен).
- Автозапуск всех компаний при старте машины (опция: положить ярлыки
  батников в автозагрузку — вручную, при необходимости).
- Учёт кредитов ImageRouter по компаниям (общий ключ; отдельные ключи
  дают раздельный учёт без доработок).
- Поддомены/реверс-прокси вместо портов.

## Проверка

1. `create_company.py` → каталог, .env, yaml, запись в реестре.
2. `start_company.bat` → сервер на своём порту; логин по паролю компании
   на `http://<host>:<порт>`; галерея/IFC пустые и не пересекаются с 9090
   и другими компаниями.
3. Два экземпляра одновременно — оба работают независимо.
4. `SITE_VALID_UNTIL` в прошлом — экран «лицензия истекла»; куки более
   не пускают.
5. Смена `SITE_PASSWORD` в `.env` компании — старая кука перестаёт
   работать, новый пароль пускает (без перезапуска).
6. `stop_company.py` — процесс остановлен, порт свободен.
