# Спека: 3D Design — криволинейные фасады + окружение (facade v2)

Дата: 2026-10-05. Ветка: `feature/studio-sso`. Сценарий: `facade`
(плитка «Facade»).

## Проблема

Пользователь генерирует 3D по фото «гнутых» зданий (пример 05.10: павильон
с волнистой крышей, сплошным остеклением и скруглённым торцем). Фасадный
конвейер строит только прямой бокс: крыши flat/gable/hip/mansard, план —
прямоугольник. Даже при плотном остеклении (фикс cols≤10→40 тем же вечером)
силуэт остаётся прямоугольным — «здание получилось прямоугольным».

Вторая половина жалобы (поздно 05.10, дамп 19:41): фасадный сценарий строит
«голое» здание — «потеряны детали сцены (окружение)»: на фото есть деревья,
люди, фоновые дома, судья-верификатор честно пишет «trees: none created,
background buildings: none identified». Окружение умеет строить только
`scene` (Exterior), но там здание — упрощённый генплан-бокс.

Цель: фото «здание + окружение» → модель с детальным гнутым зданием И
окружением (деревья, люди, фоновые дома) — одним сценарием `facade`.

Выбор пользователя (05.10, все типы): **волнистая крыша**, **скруглённые
торцы**, **изгиб в плане (дуга/банан)**, **наклонные стены** (сужение
кверху / рост высоты вдоль длины) — и **окружение** как на фото.

Подход: **параметрический контракт** (числа, не полигоны точек) — VLM
надёжно выдаёт числа, клампы/ремонт JSON работают как сейчас. Свободный
полигон силуэта отвергнут: опыт конвейера — списки точек от VLM нестабильны.

## Контракт: опциональный блок `curve` в сцене фасада

В `SYSTEM_FACADE` после `roof` добавляется блок (все поля опциональны;
отсутствие блока = прежнее поведение, старые сцены v1 совместимы):

```
"curve": {
  "silhouette": "wave" | "slope_up" | "slope_down" | null,
  "amplitude_m": <float 0.3–3.0, высота волны/подъёма линии крыши>,
  "wavelength_m": <float 4.0–40.0, только для wave>,
  "taper_pct": <int 0–40, сужение плана кверху, %>,
  "plan_bend_m": <float −15..15, прогиб дуги в плане: + к зрителю, − от>,
  "end_left": "flat" | "round", "end_right": "flat" | "round"
}
```

Семантика (H = storeys·floor_height — верх стен без кривой):
- `silhouette="wave"`: линия верха z_top(x) = H + amplitude·sin(2π(x+w/2)/λ);
  «крыша-волна» по длине (мотив павильона).
- `silhouette="slope_up"/"slope_down"`: линия верха меняется линейно
  на ±amplitude от левого торца к правому (рост/спад высоты вдоль длины).
- `taper_pct`: этаж i из n строится с масштабом плана
  s_i = 1 − taper/100 · (i+0.5)/n — стены-«лофт», сужающиеся кверху.
- `plan_bend_m`: план — дуга: передняя и задняя грани — параллельные
  параболы y(x) = ±d/2 + bend·(1 − (2x/w)²); |bend| ≤ min(w/4, 15).
- `end_left/right="round"`: торец — полукруг радиуса d/2 (аппроксимация
  10 сегментами полигона).
- Правило конфликта со старой крышей: silhouette ≠ null и roof=gable →
  приоритет у silhouette, warning «крыша заменена силуэтом-волной/склоном».

Промпт-правила SYSTEM_FACADE дополняются: «Curved buildings: estimate
amplitude/wavelength of a wavy roof line, plan bend and rounded ends
from the photo; flat rect building → omit curve». Правила «аппроксимация
призмами» из фикса №2 удаляются (нативная геометрия вместо призм).

## Контракт: опциональный блок `context` (окружение)

Схема — та же, что у `scene` (переиспользуем валидацию и сборку), в
рамке фасада: X вдоль фасада (0 = левый край, как у balconies/entrance),
Y+ — ЗА зданием (вглубь двора), Y− — перед фасадом (к камере):

```
"context": {
  "trees": [{"x_m", "y_m", "h_m": 2-20, "crown_d_m": 1-8}],
  "people": [{"x_m", "y_m", "h_m": 1.4-2.0}],
  "background_buildings": [{"x_m", "y_m" (за зданием), "w_m", "d_m",
    "h_m", "color": "#rrggbb"}]
}
```

Лимиты (кламп-дроп с warnings, как у scene): деревья ≤ 40, люди ≤ 20,
фоновые дома ≤ 8. Промпт-правило: «Report visible surroundings in
context (trees/people/background buildings); omit context for a clean
elevation/drawing». Блок опционален — старые сцены и чистые чертежи
не задеты.

## Валидация (`validate_facade`)

Разбор блока `curve` отдельной функцией `_facade_curve(raw, out, warnings)`:
- silhouette — белый список, иначе null + warning;
- amplitude 0.3–3.0, wavelength 4–40 (кламп; wavelength дополнительно
  ≤ width/1.5 — волна обязана поместиться по длине);
- taper 0–40, plan_bend |·| ≤ min(width/4, 15) (кламп);
- end_left/end_right — белый список, иначе flat + warning;
- блок не является гейтом: кривая — улучшение, любые ошибки полей = дефолт
  (null/0/flat) + warning, ValueError не бросается.

Разбор `context` — `_facade_context(raw, out, warnings)` (паттерн как у
`validate_scene`): клампы h/crown_d, дропы вне лимитов счёта; координаты
клампятся в площадку x ∈ [−10, width+10], y ∈ [−30, +60]; фоновый дом с
y ≤ depth/2+3 (перед зданием) — сброс y за фасад (depth/2+6) + warning.

## Геометрия (`build_facade`)

Тело строится из «контура плана» — полигона точек вместо прямоугольника:

- `_facade_footprint(w, d, bend, end_l, end_r, scale)` → [[x, y], …]:
  параболы передней/задней грани (шаг ~w/16), полукруглые торцы
  (10 сегментов), scale — множитель ширины/глубины для taper-этажа
  (стены-«лофт» сужаются кверху).
- Стены этажа: экструзия произвольного профиля (механизм уже есть —
  `profile.add_arbitrary_profile` + `geometry.add_profile_representation`,
  прецедент — призмы custom_parts), ObjectType как сейчас
  (CONCEPTUAL_STOREY).
- Линия верха (wave/slope): «крыша-полоса» толщиной 0.5 м — mesh
  (`_mesh_product`, прецедент — двускатная крыша) с вершинами по z_top(x);
  ObjectType CONCEPTUAL_ROOF, цвет roof.
- Окна: сетка как сейчас, но центр окна x_i проецируется на кривую передней
  грани: y_i = −d/2 + bend·(1−(2x_i/w)²), поворот окна rot_deg = угол
  нормали в точке x_i (box() уже умеет rot_deg). При round-торцах диапазон
  оконных x сужается на 0.6·d/2 с каждой стороны (warning при выкинутых
  колонках).
- Совместимость: без блока curve ни одна ветка не меняется (все
  существующие тесты обязаны проходить без правок).

Окружение (`context`): примитивы переиспользуются из `build_scene` —
деревья CONCEPTUAL_TREE (ствол+крона, 2 прокси/дерево), люди
CONCEPTUAL_PERSON, фоновые дома CONCEPTUAL_MASS-боксы с цветом. Для этого
их локальные хелперы `build_scene` поднимаются в модульные
(`_tree_proxy`, `_person_proxy`, `_bg_box`) — refactor без изменения
поведения scene (тесты scene не меняются). Счётчики фасада в
`built_overview` получают «context: trees 12, people 3, background 5».

## Превью (`_draw_facade_preview`)

Чертёж-фасад: верхняя линия повторяет z_top(x) (wave/slope), taper рисует
трапецию силуэта; при plan_bend/end_round в углу — мини-врезка плана
(вид сверху, 1:1 с превью-сеткой генплана) с дугой/торцами. Подпись
значений изгиба в шапке превью. Окружение: деревья — кружки-кроны за
силуэтом, люди — точки перед фасадом, фоновые дома — серые прямоугольники
за зданием (как на превью сцены).

## Верификация (`threed_verify`)

- `built_overview` фасада дополняется строкой кривой: «roof line: wave
  amp 1.2 m λ 9 m; plan arc bend 3.0 m to camera; ends L-round/R-flat;
  taper 10%» и строкой окружения «context: trees 12, people 3,
  background buildings 5» — судья получает факты для сверки с фото
  (снимает класс ложных issues «trees: none created»).
- Оверлей фасада (`render_overlay`): верхняя граница и окна рисуются по
  z_top(x)/пути (иначе судья видит прямую коробку и честно ругается).

## Ансамбль/регуляризация

`threed_ensemble.compare_scenes` (facade): curve-поля сравниваются как
числа/энумы (порог float как у соседей), споры — реферти как обычно.
Прогон B (grounding) кривых не извлекает: отсутствие поля у B ≠ спор.
Регуляризация кривых (v1) не делается — только compare+referee.

## Тесты (`tests/test_threed.py`, plain asserts)

1. `validate_facade`: без curve — дефолты/старые сцены не задеты; клампы
   amplitude/wavelength (в т.ч. λ ≤ w/1.5)/taper/bend; энумы → дефолт;
   wave+gable → warning о приоритете.
2. `build_facade`: wave → в IFC есть CONCEPTUAL_ROOF-элемент с >2 сегментами
   верха; arc → профиль стенового этажа содержит >4 точек (парабола);
   taper → ширина полигонов верхнего этажа меньше нижнего; round-торцы →
   в контуре плана есть точки за |x| > w/2 (полукруг).
3. Превью и `render_overlay` не падают на всех комбинациях
   (wave/arc/taper/round × 2–3 набора).
4. Роутерный мок-сценарий: сцена с curve+context → IFC создан, в
   res/overview строки кривой и окружения.
5. `context`: деревья/люди/фоны парсятся и клампятся (лимиты счёта,
   фон перед зданием — дроп+warning); `build_scene` после рефактора
   хелперов — все прежние scene-тесты без правок.

## Деплой

`setup_threed.py` + рестарт сервера (`launch\_restart_server.ps1`). UI,
роутер, фронт не меняются.
