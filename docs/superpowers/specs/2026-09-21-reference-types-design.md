# Дизайн: типы референсов для архитекторов/дизайнеров (Reference Image)

Дата: 2026-09-21. Запрос пользователя: переделать блок «Reference Image» в
левой панели — убрать настройки локальной разработки, заменить режим (Mode
«Style and Composition…») на типы референсов, характерные для работы
архитекторов и дизайнеров; вес (Weight) каждого референса учитывать в
отправляемом промте.

Скриншоты с пометками: docs/reference-block-*.png (крестики на CLIP Vision
Model (ViT-H), Begin/End % и списке Mode).

## Что убираем (настройки локальной разработки)

Из карточки референса (RefImageSettingsContent, App-бандл):

- **CLIP Vision Model** (ViT-H/ViT-G/ViT-L) — селектор локального пайплайна
  IP-Adapter; облаку значение не нужно (в графе остаётся ViT-H по умолчанию —
  билдер графа проверяет «ViT-H или ViT-G» для sdxl).
- **Begin/End %** — шаги локальной диффузии; в графе остаются [0, 1].

Селектор несущей модели («ImageRouter (референс)») оставляем: он не помечен
на удаление и гарантирует, что референс не выбрасывается из графа.

## Типы референсов (новый селектор «Тип референса»)

Значение пишется в поле `method` узла `ip_adapter` (тип и вес путешествуют
в граф штатно, без кастомных полей). Подписи — по-русски, прямо в бандле
(прецедент — «Менеджер моделей» в патче рейки).

| value | Подпись в UI | Вес по умолч. | Мини-промт (дословно в промт) |
|---|---|---|---|
| `main` | Основной | 1.0 | основная картинка: определи по ней в первую очередь композицию, ракурс, стиль и содержание |
| `extra` | Дополнительный | 0.2 | дополнительная картинка: дополняет основной ракурс деталями и уточнениями, не перебивая основной референс |
| `view3d` | 3D-ракурс | 2.0 | схема сцены кадра: выстави всё строго как на схеме — ракурс, композицию, расположение и пропорции объектов; формы и цвета самой схемы не используй, это только схема |
| `environment` | Окружение | 0.5 | окружение: возьми оттуда деревья, дорожки и благоустройство |
| `people` | Люди | 0.5 | люди: добавь людей как на этой картинке — позы, одежда, масштаб |
| `atmosphere` | Атмосфера | 0.5 | атмосфера: передай настроение картинки — освещение, время суток, погоду, цветовую гамму |
| `interior` | Предметы интерьера | 0.5 | предметы интерьера: возьми мебель и предметы (стол, стул и т.п.) как на картинке |
| `facade` | Детали фасада | 0.5 | детали фасада: оформление балконов, козырьков и фасадов целиком — как на этой картинке |
| `masterplan` | Генплан | 0.5 | генплан: возьми только расположение зданий как на схеме |

Веса 1 / 0.2 / 2 заданы пользователем; остальным по умолчанию 0.5 (пользователь
двигает слайдер Weight 0–2 под задачу). **Выбор типа выставляет Weight на
дефолт типа** (патч колбэка в RefImageSettingsContent); фактическое значение
слайдера уходит в граф и в промт.

Новые референсы создаются сразу типом «Основной» (патч дефолта конфига в
index-бандле: `method:"full"` → `method:"main"`). Zod-enum `method` (2 вхождения
в index-бандле: схема узла + валидатор) расширяется нашими девятью значениями.

Старые сессии с method `full`/`style`/… — селектор покажет плейсхолдер, в граф
уйдёт старое значение; роутер трактует неизвестный тип как универсальный
референс (см. ниже).

## Формирование промта (роутер)

Промт пользователя и Template уже объединяет клиент (шаблон вставляет промт
в `{prompt}` либо дописывает после него) — роутер получает готовый текст.
Далее роутер (вместо прежних общих PROMPT_REFERENCE_ROLES_NOTE /
PROMPT_REFERENCE_NOTE) дописывает блок референсов:

```
Первое изображение — исходник для редактирования.      ← только если есть исходник
Изображение 2 — основной референс (вес 1): основная картинка: …
Изображение 3 — 3D-ракурс (вес 2): схема сцены кадра: выстави всё строго как на схеме…
```

- Нумерация соответствует массиву `image[]` edits-запроса (исходник — №1,
  референсы дальше).
- Вес — из `ip_adapter.weight` узла; отсутствует/невалиден — дефолт типа.
- Неизвестный тип (старые значения, референс добавлен Generate-фолбэком):
  «референс (общий): учитывай стиль и содержание этой картинки».

`_extract_ir_info` собирает `ref_details` [{image, type, weight}] параллельно
списку имён (имена в `references` остаются — совместимость); метаданные
результата пополняются `ref_details`, лог enqueue печатает типы/веса.

## Изменения файлов

- `imagerouter/imagerouter_router.py`: реестр IR_REF_TYPES; сбор
  method/weight из ip_adapter-узлов; сборка блока референсов в промте;
  метаданные/лог. Удаление PROMPT_REFERENCE_* (в новой сборке не нужны).
- `setup_imagerouter.py`: `patch_reference_types()` — 4 замены в App-бандле
  (опции+лейбл IPAdapterMethod; убрать CLIP Vision; убрать Begin/End;
  авто-вес при смене типа) и 2 в index-бандле (дефолт rS, zod-enum ×2);
  вызов в main(); идемпотентность маркером `value:"view3d"`.
- `tests/test_reference_types.py`: якоря в живых бандлах, патч на синтетике
  (идемпотентность), _extract_ir_info на фейковом графе, текст промта.

## Проверка

`venv\Scripts\python.exe setup_imagerouter.py` → node-import обоих бандлов
(только runtime-ошибка, не SyntaxError) → рестарт `_restart_server.ps1` →
E2E в браузере: карточка референса без CLIP Vision/Begin-End, селектор
«Тип референса» с 9 типами, смена типа двигает Weight, генерация с
референсами (в `_ir_last_graph.json` узлы ip_adapter несут method/weight;
в промте — блок референсов). Тест: `venv\Scripts\python.exe
tests\test_reference_types.py`.
