# Спека: настройки Design Code и владельца — в админ-панель

Дата: 2026-10-08. Ветка: `user`.

## Контекст

После переезда на новый сервер у владельца будет ограниченный доступ к
файлам (`.env`, скрипты). Настройки, которые сейчас правятся только руками
в `.env`, нужно вынести в веб-админку `/admin` (режимы users/sso):

- `DESIGN_CODE_URL` / `DESIGN_CODE_ACCESS_CODE` — адрес сайта дизайн-кода
  и код доступа (общие для инстанса, из `.env`);
- `SITE_PASSWORD` — пароль владельца (вход с пустой почтой);
- `IMAGEROUTER_API_KEY` — глобальный ключ ImageRouter (генерации
  владельца admin-local и админов без персонального токена).

Запрос пользователя: в админке напротив каждого клиента — два поля
(URL сервиса дизайн-кода и токен доступа), т.е. ПЕРСОНАЛЬНЫЕ настройки
Design Code; плюс «подумай, что ещё» перенести из `.env`.

Клиенты = пользователи базового инстанса (режим users; компании-лицензиаты
— отдельные инстансы в password-режиме, там своей админки нет и `.env`
остаётся источником).

## Решение

### Хранилище (studio_store.py)

- Новая таблица `settings(key TEXT PRIMARY KEY, value TEXT NOT NULL)` —
  общие настройки инстанса. Ключи: `design_code_url`,
  `design_code_access_code`, `site_password`, `imagerouter_api_key`.
  Функции `get_setting(key)` / `set_setting(key, value)` (пустое значение
  или None → строка удаляется — «как в .env»).
- Колонки `users.dc_url`, `users.dc_code` (миграция в `init_db`, как
  password_hash/ir_token). Функция `set_design_code(user_id, url, code)`
  (None/пусто → NULL).

### Разрешение настроек Design Code (design_code_router.py)

Поля НЕЗАВИСИМЫ, цепочка на каждое (первое непустое выигрывает):

- URL: персональный (`users.dc_url`) → общий (`settings.design_code_url`)
  → `.env DESIGN_CODE_URL` → os.environ → нет.
- Код: персональный (`users.dc_code`) → общий
  (`settings.design_code_access_code`) → `.env` → os.environ → защита
  выключена.

Пользователя роутер берёт из заголовка `x-studio-user` (его инжектит
SiteAuthMiddleware во все `/api/` запросы; password-режим — заголовка
нет, работают только общие цепочки). admin-local без персональных
настроек → общие. GET/POST `/api/v1/designcode/auth` семантику не меняют:
`protected` = код разрешён, `default_url` = префилл. Страница вьювера
НЕ меняется.

### Админ-API (site_auth.py, гейт admin как у соседних)

- `POST /admin/api/users/{uid}/designcode` `{url, code}` — персональные
  поля (пустые → очистить). URL пуст или http(s)://, ≤2048.
- `GET/POST /admin/api/settings/designcode` `{url, code}` — общие.
- `POST /admin/api/settings/site-password` `{password}` — ≥8 символов,
  пишется в `settings.site_password`; `_site_password()` читает
  settings → `.env` → `devbim` (password-режим компаний не тронут:
  у них settings пустые).
- `POST /admin/api/settings/ir-key` `{key}` — пишется в
  `settings.imagerouter_api_key`; `_load_key()` imagerouter читает
  settings → `.env` → ключевой файл. Пусто → очистить.
- `GET /admin/api/users` отдаёт `dc_url`/`dc_code` (видит только админ).

### Админ-панель (UI /admin)

- В таблице пользователей колонка «Design Code»: кнопка с хостом
  персонального URL или «— общие —»; клик — модалка «URL сайта» +
  «Код доступа» (Сохранить / Очистить персональные / Отмена) с
  подсказкой, что сейчас действует (общие значения).
- Блок «Общие настройки» над таблицей: Design Code (URL + код),
  пароль владельца, глобальный ключ ImageRouter (маскированное поле).
  Изменения действуют сразу (все читаются на каждом вызове), рестарт
  не нужен.

## Не-цели

- Блокировка произвольного URL у клиента (кнопка «Change site» вьювера
  сохраняется — код по-прежнему гейтит открытие любого адреса).
- `ADMIN_PASSWORD` (гейт Model Manager актуален только в password-режиме
  компаний, где админки нет), `STUDIO_*` секреты, `SITE_VALID_UNTIL`
  (лицензии компаний) — остаются в `.env`.
- Ротация кода «на лету» у уже разблокированной вкладки — sessionStorage
  `unlocked` живёт до закрытия вкладки, как раньше.

## Тесты

- `tests/test_designcode.py`: пер-пользовательские и общие настройки,
  приоритеты (персональный > общий > .env), пустые = фолбэк; UI-фрагменты
  страницы не тронуты.
- `tests/test_site_auth.py`-паттерн для admin-API: гейты (401/403),
  валидация URL/пароля, чтение settings в `_site_password`/`_load_key`.

## Деплой

`setup_designcode.py` + `setup_site_auth.py` (роутер и мидлварь в venv),
imagerouter-роутер — `setup_imagerouter.py`, рестарт
`launch\_restart_server.ps1`. Миграция БД — автоматически в `init_db`.

## Обновление (п.74, тот же день): один дизайн-код = один клиент

Запрос пользователя: «настройки дизайн-кода будут только для одного
пользователя, т.е. соответствующий дизайн-код доступен только 1
пользователю (например, nw@devbim.com); новых дизайн-кодов пока не
планирую». Прежняя семантика «нет кода → вкладка открыта любому URL»
этому противоречила.

Новая семантика (`_resolve_dc(uid) -> (url, код, denied)`):

- обычный пользователь (role=user, режимы users/sso) — ТОЛЬКО его
  персональные dc_url/dc_code; персонального кода нет → `denied`:
  GET /auth `{denied:true, protected:true, default_url:null}`,
  POST /auth — 403 «Доступ к дизайн-коду не выдан»;
- владелец/админы и password-режим — прежняя цепочка персональное →
  settings → .env (роль смотрится в studio_store.effective_role);
- вьювер: `status.denied` → карточка «Access … has not been granted»
  вместо формы (форма скрыта);
- админка: у пользователя без персональных настроек кнопка «— закрыто —»,
  подсказки общих настроек уточнены (действуют для владельца/админов).

Настройка живого сервера 08.10: nw@devbim.com — персональные URL+код
базы «Северного берега»; общие settings = значения .env (владельцу);
остальные пользователи — вкладка закрыта.
