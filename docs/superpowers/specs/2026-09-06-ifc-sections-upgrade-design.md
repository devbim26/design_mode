# Дизайн: модернизация сечений IFC-вьювера

Дата: 2026-09-06. Запрос пользователя: вертикальные сечения (сейчас только
горизонтальное), скрытие плоскости сечения без отмены самого сечения,
«что-то ещё в этом направлении».

## Что есть сейчас

`ifc/ifcviewer.html` (@thatopen/components 3.4.8): кнопка «Сечение» создаёт
ОДНУ горизонтальную плоскость (`clipper.createFromNormalAndCoplanarPoint`,
нормаль (0,-1,0), 75% высоты), кнопка «✕ сечения» удаляет все. Helpers
плоскостей всегда видимы, перетаскиваются стрелкой (TransformControls).

## Что делаем

Кнопки «Сечение» и «✕ сечения» в тулбаре заменяются одной кнопкой
«Сечения ▾», открывающей всплывающую панель (в т.ч. в embed-режиме панели
«IFC Viewer» на холсте). Всё — внутри ifcviewer.html, бандлы не трогаем,
деплой штатным `setup_ifcviewer.py` (копия страницы as-is).

### Панель «Сечения»

1. **Создание** — три кнопки:
   - «Горизонтальное» — нормаль (0,-1,0), точка = центр bbox + 0.25·size.y
     (как сейчас: срезает верх, план этажа);
   - «Вертикальное X» — нормаль ±X, точка = центр bbox; знак нормали
     выбирается по камере: срезается половина, обращённая к наблюдателю;
   - «Вертикальное Z» — аналогично по оси Z.
2. **«Показывать плоскости»** — глобальный тумблер `clipper.visible`:
   скрывает/показывает ВСЕ helpers (квадраты и стрелки). Само сечение
   (клиппинг) продолжает действовать — запрос пользователя. Когда helpers
   скрыты, перемещать сечения можно слайдером.
3. **Список активных сечений** — по карточке на плоскость (`clipper.list`):
   - заголовок («Горизонтальное 1», счётчики по типам) + текущая координата
     вдоль оси (м, 2 знака: «отм. +3.25 м» / «x = −2.10 м»);
   - **слайдер** — позиция плоскости вдоль оси нормали в пределах bbox
     модели (шаг = диапазон/400); тянет плоскость и вживую, и обновляется
     после перетаскивания стрелки мышью (событие `clipper.onAfterDrag`);
   - **⇄ флип** — развернуть сторону отсечения (нормаль → −нормаль);
   - **👁 видимость** — скрыть/показать helper конкретной плоскости
     (`plane.visible`, клиппинг остаётся);
   - **✕ удалить** — `clipper.delete(world, id)`.
4. **«Удалить все»** + подсказка «плоскость тянется мышью за стрелку».

### Технические решения (вы verified по бандлу 3.4.8)

- Перемещение/флип — своя функция вместо `plane.setFromNormalAndCoplanarPoint`
  (в библиотечной версии `reset()` вызывают `helper.lookAt(normal)` ДО
  сброса позиции helper — при флипе к нормали (1,0,0) ориентация helper
  ломается): копируем normal/origin, ставим
  `helper.quaternion.setFromUnitVectors(ẑ, normal)`, позицию, `update()`
  (синхронизирует `three.plane` → клиппинг в рантайме, объекты плоскостей
  в материалах те же самые).
- Живая позиция читается из `plane.helper.position` (не `plane.origin` —
  тот не синхронизируется при drag).
- Ось плоскости = доминанта `plane.normal` (|n.y|≥|n.x|,|n.z| → Y и т.д.).
- `clipper.visible=false` скрывает helpers всех плоскостей, `=true` —
  показывает все (включая ранее скрытые по отдельности — принято).
- Сечения переживают перезагрузку модели (как раньше), слайдеры
  пересчитываются под новый bbox.
- Панель закрывается по ✕, ESC, клику вне; CSS — существующая тёмная тема.

### Ограничения (принято)

- Плоскости только осевые (X/Y/Z) — произвольный угол не даём (YAGNI;
  Revit-подобного «сечения по линии» нет).
- Кэпcamerа-зависимый знак нормали вертикалей — только в момент создания.

## Тестирование

- `tests/test_ifc_sections.py`: структура страницы (id новых элементов,
  отсутствие старых кнопок), функции создания/флипа/слайдера в исходнике,
  деплой setup_ifcviewer.py разворачивает новую страницу в dist.
- Синтаксис module-скрипта — извлечь в .mjs и `node --check`.
- Живой прогон в браузере (Playwright): модель с сервера → все три типа
  сечений → скрытие плоскостей → флип → слайдер → скриншоты.

# Дополнение (06.09, вечер): «Человек» — силуэт + камера от глаз (как SketchUp)

Запрос: силуэт человека, ставится кликом, «автоматом привяжется к
перекрытию», камера с глаз человека высотой 1,7 м (Position Camera / Walk
в SketchUp).

## Что делаем

Кнопка тулбара «👤 ▾» → панель «Человек»:

1. **Постановка**: «Поставить на перекрытие» включает режим постановки;
   следующий клик по модели ставит человека (один, заменяемый).
   Привязка к перекрытию: из точки клика вертикальный луч ВНИЗ
   (+0,1 м над точкой) — попадает в ту же поверхность, если кликнули
   горизонтальную плоскость (перекрытие/пол/крыша), либо в пол ПОД
   стеной, если кликнули вертикальную грань. Луч — штатный
   `fragments.raycast` с ВРЕМЕННОЙ камерой, смотрящей строго вниз
   (ray строится setFromCamera от переданной камеры; мышь = центр
   канваса). Нет попадания — берём y клика как есть.
2. **Силуэт**: биллборд PlaneGeometry 0.55×1.75 м с CanvasTexture
   (стоящая фигура, полупрозрачная), ноги на земле; в rAF
   разворачивается по азимуту камеры (как 2D-люди SketchUp). Маркер
   глаз — маленькая сфера на 1,7 м.
3. **Вид от глаз (1,7 м)**: вход — камера в глаза человека, controls
   выключаются, поза орбиты и проекция сохраняются; осмотр — перетаскивание
   ЛКМ (yaw/pitch, Euler YXZ, pitch ±85°); ходьба — WASD/стрелки по
   горизонту от yaw (1,6 м/с, Shift ×3) в rAF-цикле; человек следует за
   камерой по x/z с периодической перепривязкой к полу (тот же
   вертикальный луч, троттлинг ~150 мс); ESC/кнопка — возврат к орбите
   (setLookAt сохранённой позы, восстановление проекции). Силуэт в FP
   скрыт (он и есть «вы»). `fragments.core.update()` при движении —
   свежий LOD.
4. **Прочее**: «Убрать человека»; ESC отменяет режим постановки; при
   загрузке ДРУГОЙ модели человек убирается (не парит в чужих
   координатах); отладка `window.__ifc.person` (place/enterFP/exitFP/
   remove/state).

## Решения/грабли

- Версия @thatopen: у Event подписка `.add()`; рендер непрерывный
  (Components.update rAF) — ручная камера и биллборд отображаются без
  доп. триггеров.
- Сечения и человек: плоскости клиппинга лежат в глобальном
  renderer.three.clippingPlanes — человек, стоящий в срезанной зоне,
  скроется вместе с моделью (как в SketchUp, принято).
- `controls.enabled = false` на время FP; коллизий нет (проходим сквозь
  стены — уровень SketchUp Walk без гравитации по лестницам).

# Дополнение 2 (06.09, ночь): тень + BIM-контекст промта + архитектурная камера

Утверждено пользователем («ок») после обзора кандидатов на улучшение
ИИ-рендеринга. Быстрые победы одним заходом:

1. **Контактная тень в снимке.** В renderSnapshot: 4 нижних угла bbox
   модели проецируются камерой на экран; если все перед камерой —
   радиальный градиент-эллипс по их bounding box (затемнение ~0.35,
   расширение ~10%) рисуется на промежуточный канвас ДО наложения
   WebGL-кадра — виден только в прозрачных полях, здание «стоит» на
   земле. Отключено в FP-режиме (интерьер от глаз) и когда основание
   за камерой/за кадром.

2. **BIM-контекст для промта.** При построении дерева строится карта
   localId → {storey, space} (ближайшие предки IFCBUILDINGSTOREY /
   IFCSPACE); имена помещений — ОДНИМ пакетным getItemsData по всем
   IFCSPACE. Источник контекста: элемент клика при постановке человека
   (обновляется при ходьбе — localId из snap-луча) либо текущее
   выделение. Строка: `BIM context: floor "…", room "…"` (+ `selected:
   IfcWall` при выделении). UI: поле только-чтение в панели «Человек»
   (клик — выделить всё); при «📸 To Canvas»/«💾 To Assets» строка
   копируется в буфер (navigator.clipboard, фолбэк execCommand) и
   упоминается в тосте — пользователь вставляет в промт (Ctrl+V).

3. **Архитектурная камера — панель «📷 ▾» в тулбаре:**
   - ползунок **FOV 20–90°** (threePersp.fov + updateProjectionMatrix);
   - **«⌷ Вертикали»** — в FP: pitch→0 (двухточечная перспектива),
     горячая V; вне FP — подсказка;
   - **«— Горизонт»** — выровнять орбиту: полярный угол → 90° при тех же
     азимуте/дистанции/цели (setLookAt);
   - **«▦ Орто-фасад»** — ортографический фронтальный вид: нормаль из
     последнего raycast-выбора (hit.normal), иначе ось X/Z к камере;
     projection.set("Ortho") + камера по нормали на дистанции
     maxDim*1.6, взгляд в центр bbox; кнопка **«◐ Перспектива»**
     возвращает;
   - **рамка кадра**: select (выкл, 1:1, 3:2, 2:3, 16:9, 9:16, 4:5,
     3:4) — пунктирный оверлей по центру вьюпорта; renderSnapshot
     кадрирует по рамке (координаты рамки × DPR, кратно 64 через
     snap64, пропорции сохраняются, поля прозрачные).

Тесты: tests/test_ifc_ai_render.py (разметка/логика/деплой).
