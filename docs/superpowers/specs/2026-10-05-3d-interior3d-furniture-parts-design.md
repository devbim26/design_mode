# Спека: 3D Design Interior — мебель из деталей (furniture-parts)

Дата: 2026-10-05. Ветка: `feature/studio-sso` (продолжение `interior3d`).

## Проблема

Пользователь: «для 3D интерьера получаются слишком примитивные объекты,
преимущественно кубы, потом не понятно где что». Причины в текущей сборке
(`build_interior3d`):

1. Каждый предмет мебели — ОДИН бокс `w×d×h` (`box(...)`): кровать, диван
   и шкаф выглядат одинаковыми параллелепипедами.
2. Человек — один бокс 0.5×0.3×h.
3. `rot_deg` определён только как «0 = длинная сторона вдоль X»: у
   асимметричных предметов (диван со спинкой, кровать с изголовьем) не
   закодировано, где перед/спинка — «не понятно где что».
4. Превью-план без подписей: типы предметов не читаются.

## Решение

### 1. Библиотека параметрических деталей (threed_build)

Каждый предмет — родитель `IfcFurnishingElement` (БЕЗ геометрии,
ObjectType `FURNITURE_<TYPE>` как раньше) + 1–7 деталей-боксов
`IfcFurnishingElement` с ObjectType `FURNISHING_PART`, агрегированных в
родителя через `IfcRelAggregates` (структурный verify п.58 считает
агрегацию привязкой ✓; verify-судья кросс-чекает counts по
`FURNITURE_<TYPE>` — parents сохраняют 1:1 со сценой, части уходят в
отдельный бакет `FURNISHING_PART`).

Композиции (локальный ЛОКАЛЬНЫЙ фрейм предмета: x∈[−w/2,w/2],
y∈[−d/2,d/2], перед = +Y; размеры — доли w/d/h с min-гейтом 0.03 м,
мелкие части при мелком предмете пропускаются):

- bed: каркас, матрас (акцент #e8e2d4), изголовье у −X, 2 подушки
  (#f2efe6), одеяло (затемнение основного цвета ×0.82);
- sofa/armchair: основание, спинка у −Y, 2 подлокотника, 1–2 подушки
  сиденья (осветление ×1.15);
- chair: сиденье, спинка, 4 ножки (акцент-дерево #6b5b47);
- table/desk: столешница + 4 ножки / 2 боковины + задняя панель;
- wardrobe: корпус + 2 двери (фронты выступают +0.01 из грани — урок
  фазы 2 о совпадающих гранях);
- kitchen: тумбы + столешница (осветление ×1.25) + верхние шкафы
  (w×(d−0.22)×0.65 от z=1.45 — только если высота комнаты ≥ 2.2 и
  хватает места);
- tv: экран (#14171c) на подставке (#3a3f46);
- rug: кайма (затемнение ×0.8) + основа;
- plant: горшок (#8a5a3c), ствол (дерево), крона (#4e7a4e);
- lamp: база + стойка (#4a4f55) + абажур (#f0d68a);
- nightstand/dresser: корпус + 2/3 фронта ящиков;
- shelf: 2 боковины + 5 полок + задник;
- toilet: чаша + бачок (фарфор #e8ecef); sink: тумба + чаша;
  bathtub: корпус + «вода» (#cfe3ec);
- other: один бокс (как раньше).

Хелпер `_shade(hex, f)` — затемнение/осветление цвета предмета (VLM hex
или дефолт типа); стили деталей через `_ensure_style` с ключами
`acc:<имя>` / `i3dsh:<hex>`.

### 2. Ориентация: front-facing семантика rot_deg

Локальный фрейм: перед предмета = +Y. Два класса типов:

- **FRONT_Y** (диван/кресло/стул/шкаф/кухня/ТВ/письменный стол/тумба/
  комод/стеллаж/унитаз/раковина/other): поворот размещения θ = −rot_deg;
  «0 = перед смотрит на север +Y, длинная сторона вдоль X» — та же
  семантика, что у `people.rot_deg` (0=север, 90=восток). Проверка:
  R(−rot)·(0,1) = (sin rot, cos rot) ✓.
- **Остальные** (bed/table/rug/plant/lamp/bathtub — «длинная сторона
  вдоль X» без переда): θ = +rot_deg (старое поведение). Исключение —
  bed: изголовье у локального −X, «0 = длинная сторона вдоль X, изголовье
  на западе».

Люди: 3 части (ноги 0.45h, торс 0.40h, голова 0.14h + кожа #d8b89a),
родитель `CONCEPTUAL_PERSON` + части `CONCEPTUAL_PERSON_PART`; θ = −rot
(раньше знак не имел значения из-за симметрии бокса — теперь важен).

Окна: родитель `CONCEPTUAL_WINDOW` + рама (#f2f0ea) + стекло
(`CONCEPTUAL_WINDOW_PART`, #A8D4EA с Transparency 0.55 — полупрозрачное).
Двери — без изменений (один бокс).

### 3. Новые типы мебели (словарь + промпт + дефолты)

`nightstand` (0.5×0.4×0.55, «Тумба»), `desk` (1.2×0.6×0.75, «Стол
письменный»), `shelf` (0.9×0.35×1.8, «Стеллаж»), `dresser`
(1.2×0.5×0.85, «Комод»), `toilet` (0.4×0.65×0.75, «Унитаз»), `sink`
(0.6×0.45×0.85, «Раковина»), `bathtub` (1.7×0.75×0.55, «Ванна») —
зеркалируют типы сценария `interior` (Floor Plan). Валидатор — только
расширение `INTERIOR3D_FURNITURE_TYPES` (новый тип = дефолтные габариты,
без warning).

### 4. SYSTEM_INTERIOR3D (промпт VLM)

- enum типов + 7 новых; правило «предпочитай конкретный тип вместо
  other»;
- rot_deg: две строки семантики (front-facing для посадочных/фронтальных,
  изголовье для кровати);
- правило: честно указывай, куда повёрнут перед (спинка дивана к стене,
  изголовье кровати к стене, экран ТВ к дивану).

### 5. SYSTEM_VERIFY (судья)

В «Tolerate» добавлена строка: мебель/люди собираются из под-объёмов
(`FURNISHING_PART`, `*_PART` — это детали одного предмета; counts
сравнивать по `FURNITURE_<TYPE>` / `CONCEPTUAL_PERSON`).

### 6. Превью-план

- Подписи предметов: короткое русское имя + номер (fontsize ~5.5, белая
  подложка); для мелких (w<0.5) — только номер.
- Носик-стрелка направления «перед» для FRONT_Y-типов; метка
  изголовья у кровати; человек — круг + голова-точка + носик.
- Поворот следов: θ (для FRONT_Y это −rot_deg).

### 7. pset RoomModel

+ `FurnitureParts` — суммарное число деталей (для контроля).

## Границы (не делаем)

- Не трогаем `interior` (Floor Plan), `scene`, `facade`, ансамбль.
- Без фасок/цилиндров/мешей у мебели — только боксы (быстро, читаемо,
  концептуальная модель); вставка реальной мебельной геометрии (bрамя
  IFC-библиотек) — отдельная тема.
- Пересечения деталей между предметами не решаем (ApproximateGeometry).
- Камера/вьювер не меняются.

## Риски

1. `aggregate.assign_object` на IfcFurnishingElement — если API
   откажет, fallback: плоские части в storey (имена «Диван 01 · спинка»).
2. web-ifc дерево: части попадают в дерево через IfcRelAggregates
   (стандарт web-ifc); если во вьювере не появятся — рендер всё равно
   полный (геометрия не зависит от дерева), камера interior не зависит
   от fit.
3. VLM перепутает перед/спинку — теперь это видно (спинка не к стене),
   ловится verify-петлёй; клампов не требует.
