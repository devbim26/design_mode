# Спека: «3D Design» — генерация IFC-модели по картинке (фасад / интерьер / генплан)

Дата: 2026-09-18. Запрос пользователя: «в системе есть кнопка 3d… нужна
для особого режима генерации 3d модели по загруженной картинке из холста
+ промт»; уточнения в диалоге: три сценария (фасады, интерьеры,
генпланы), анализ делает ИИ-модель (дефолт GPT-6-Astra через
ImageRouter, выбирается в менеджере), модель возвращает подробный
JSON-сцены, наш сборщик на IfcOpenShell строит IFC, результат — в
существующей вкладке IFC-вьювера.

## Контекст

- Кнопка «3D Design» уже есть — заглушка с тостом «раздел в разработке»
  (`imagerouter/devbim_topright_buttons.js`, п.35 HANDOFF).
- Готовая инфраструктура: ImageRouter chat completions (Prompt
  Enhancer, п.22 — паттерн ленивого ключа/модели из .env), IFC-вьювер
  со списком моделей `data/ifc/` и автозагрузкой последней
  (`devbim:ifc:lastModel`, п.12–13), админ-менеджер выбора моделей
  (п.27/28), мост `__devbimCanvasBridge`, DTO картинок
  `POST /api/v1/images/images_by_names`, конвейер «IFC → снимок → To
  Canvas → ИИ-рендер».
- Агентный скилл image-to-ifc с проверенными `build_model.py` /
  `test_model.py` (footprints.json → валидный IFC4) — основа режима
  «Генплан».
- Каталог ImageRouter (проверено 18.09, 400 моделей): `openai/
  gpt-6-astra` — VLM (вход text+image, выход text; вход-картинка
  бесплатно, completion $50/M токенов; поддерживает max_tokens,
  response_format). Моделей с 3D-меш-выходом в каталоге НЕТ.
- MCP4IFC (препринт Show2Instruct) рассматривался и отклонён: реальный
  код (`ifc-bonsai-mcp`) требует Blender+Bonsai в рантайме, MCP-протокол
  в нашей архитектуре — лишнее звено, зрелость research. Полезная суть
  (LLM + инструменты над IfcOpenShell) учтена как этап развития.

## Решение

### Конвейер (общий для всех сценариев)

1. Клик «3D Design» → **модалка**: выбор сценария (Генплан / Фасад /
   Интерьер), превью картинки-источника, textarea промта, Generate.
2. **Источник картинки**: активна вкладка «Холст» и есть контент —
   композит холста (`stage.toCanvas` через
   `__devbimCanvasBridge.getManager()`); иначе — выбранная во вьювере
   картинка (`state.gallery.selection` → `images_by_names` → fetch →
   dataURL); нет ни того, ни другого — подсказка «положите картинку на
   холст или выберите в галерее».
3. `POST /api/v1/threed/generate` `{scenario, prompt, image}` (image =
   dataURL PNG) — синхронный запрос (таймаут 300 с), модалка крутит
   прогресс с секундами.
4. Сервер: системный промпт сценария + картинка (даунскейл до 1536 px
   по длинной стороне, PNG) + пользовательский промпт → chat
   completions **VLM-модели, выбранной в менеджере** → строгий
   JSON-сцены.
5. Валидация + автопоправки: clamp координат в границы картинки,
   дефолты этажности/высот, битые секции выбрасываются с записью в
   допущения; невалидный JSON → один ретрай «верни только валидный
   JSON» → при повторном провале 422.
6. Сборщик `threed/build_ifc.py` (ifcopenshell + shapely) → IFC4 →
   `data/ifc/3D_<plan|facade|interior>_<ГГГГММДД-ЧЧММ>.ifc` (имя
   Windows-safe) + `<имя>_preview.png` рядом (в список вьювера не
   попадает — роутер листает только `*.ifc`).
7. Ответ `{name, warnings[]}` → виджет: `localStorage
   devbim:ifc:lastModel = name` + `__devbimSwitchTab('ifc')` → вкладка
   IFC автозагружает модель (см. «Вьювер»). Дальше штатный цикл
   (сечения, человек, камера, To Canvas → ИИ-рендер).
8. У каждого продукта pset `DevBIM`: Source=«3D Design», Scenario,
   Prompt, Model, `ApproximateGeometry=True`, Assumptions (строки
   допущений — масштаб, этажность по умолчанию, орто-допущение и т.п.).

Разделение ответственности: LLM отвечает за анализ (что видно на
картинке), код — за валидность IFC (STEP-синтаксис, GlobalId, замкнутость
тел гарантирует сборщик). Ни одна генерация не выдаёт битый файл.

### Модель в менеджере

- Файл `data/imagerouter_threed_model.json` (per-company):
  `{"model": "openai/gpt-6-astra"}`. Цепочка: файл → `.env
  THREED_MODEL` → дефолт `openai/gpt-6-astra`.
- `GET/PUT /api/v1/threed/model`; PUT валидирует: модель есть в
  каталоге v3, `input_modalities` содержит image, `output_modalities`
  содержит text (иначе 422 со списком подходящих VLM).
- Админ-секция «3D-генерация — модель аналитики» в imagerouter.html:
  выпадающий список VLM каталога (фильтр по модальностям, кэш каталога
  10 мин), активная модель, подсказка про F5.

### Сценарий «Генплан» (топ-даун схема/аэро)

- Схема = footprints.json скилла: `sections[{id, building, use:
  Residential|School|Kindergarten, floors, points[[x,y],…]}]` в
  координатах картинки (trace_width/height = размеры исходной
  картинки), `context[{kind: Ground|Road|Parking|Sport|Court|Play,
  z, depth, points}]`, `metres_per_trace_pixel` (Astra оценивает по
  опорам: спортплощадка ≈16–18×32–36 м, машиноместо 2,5×5 м; промт
  может задать масштаб явно), высоты этажей жилые/общественные.
- Сборка: поэтажные объёмы (IfcProject → Site → Building → Storey →
  BuildingElementProxy, SweptSolid-экструзии), цвета по типам,
  плиты контекста. Код — адаптация `build_model.py` скилла.
- Превью: обводки + этажность поверх исходной картинки (как
  `_footprints.png` скилла) + 3D-превью.

### Вьювер (малый патч ifcviewer.html)

Сейчас автозагрузка `devbim:ifc:lastModel` и storage-синхронизация
живут только в embed-панели (блок `if (EMBED)`, строки ~1769–1813).
Выносим автозагрузку последней модели на старт ПОЛНОЙ вкладки IFC
(iframe монтируется свежим при переключении — прочитает только что
сгенерированную модель; кнопка «3D» на вкладке IFC скрыта, спорных
перезаписей нет). Селектор моделей в шапке вкладки остаётся. Деплой —
`setup_ifcviewer.py` (копия as-is, идемпотентно).

### Сценарий «Фасад» (фото/рендер фасада ИЛИ чертёж фасада)

Вход — оба варианта (решение пользователя 18.09): фото существующего
здания / ИИ-рендер фасада, либо чертёж фасада с размерными линиями.
Системный промпт: если на картинке есть размерные линии — масштаб
считать по ним (точнее); иначе — по опорам (окно ≈1,5 м, этаж ≈3 м).

- Схема: `storeys`, `floor_height` (м), `width_m`, `depth_m` (с фасада не видна — дефолт 12 или из промта),
  `roof: flat|gable` + `roof_height`, `windows {rows, cols, w_m, h_m,
  margin_x_m, margin_y_m, skip[][] (опциональная bool-матрица
  пропусков)}`, `balconies[{floor, x_m, w_m, d_m}]`,
  `colors {walls_hex, roof_hex, plinth_hex}`.
- Сборка: объём здания (бокс или бокс + двускатная призма крыши),
  поэтажная структура, окна — тёмные параллелепипеды-«стеклопакеты»
  заподлицо с лицевой гранью (равномерная сетка с пропусками),
  балконы — плиты. Допущения (в свойствах): перспектива принята за
  орто, глубина типовая.

### Сценарий «Интерьер» (план квартиры/помещения)

Вход — 2D-план (скачанный чертёж, постраничный фрагмент PDF, скрин),
НЕ фото готового интерьера. Пользовательский цикл (зачем это нужно):
план → 3D → во вьювере поставить человека (п.25), вид от глаз,
развернуть камеру → 📸 снимок нужного ракурса → снимок + реальные фото
предметов (стул, лампа…) как Reference Images + промт («стены
покрась…») → генерация интерьера ИМЕННО с того ракурса и с теми
предметами. Всё после «снимка» уже работает штатно (п.25/26: постановка
человека, BIM-контекст, референсы) — нового ничего не требуется.

- Схема: `metres_per_trace_pixel` (опоры: дверной проём 0,9–1 м,
  кровать 2×1,6 м, унитаз 0,4 м; на планах бывает размерная линия —
  тогда считать по ней), `wall_height` (дефолт 2,7), `outline
  [[x,y],…]` — наружный контур, `walls [{points:[[x1,y1],[x2,y2]],
  thickness_m, exterior}]`, `openings [{wall_idx|“outline”, x_m,
  width_m, height_m, sill_m, kind: door|window}]`, `rooms [{name
  (прочитанная с плана подпись: «Кухня»…), type, points}]`,
  `furniture [{type: bed|sofa|table|chair|wardrobe|kitchen|bath|
  toilet|sink|lamp|other, x_m, y_m, w_m, d_m, h_m, rot_deg}]`
  (позиции/поворот — как нарисовано на плане).
- Сборка: плита пола, стены боксами по сегментам (толщина с плана),
  окна/двери — тёмные прямоугольники заподлицо с плоскостью стены,
  комнаты — **IfcSpace с именами** (выбор кликом во вьювере покажет
  «Кухня»), мебель — **типизированные элементы** (IfcFurnishingElement
  с ObjectType) цветными боксами по палитре типов (паттерн цветов
  зданий скилла), поворот через placement.
- «Обозначение объектов сцены» (запрос пользователя) = имена комнат +
  типы мебели + цвет по типу в 3D + штатный BIM-контекст у постановки
  человека (п.26: строка «floor …, element …» для промта). Подписи
  объектов прямо на снимке — кандидат на продолжение.
- Ожидания зафиксированы: концептуальная «квартира с блоками» для
  ракурсов и планировки; фотореалистичность даёт второй этап
  (снимок + референсы + ИИ-правка), а не 3D-модель.

### UI-модалка

- DOM-модалка в `devbim_topright_buttons.js` (паттерн devbim_admin.js):
  заголовок «3D Design», три плитки сценариев (иконки: карта /
  здание / комната), превью источника (~240 px, бейдж «Canvas» /
  «Viewer»), textarea промта (placeholder с примерами по сценарию),
  Generate (акцент кнопки 3D #A78BFA), строка прогресса с секундами,
  Esc/✕ — закрыть.
- RU/EN тексты по языку интерфейса (IndexedDB-поллинг уже в виджете).
- Во время запроса Generate disabled; успех → тост «Модель создана:
  <имя>» + переход на вкладку IFC; warnings (допущения) — строкой под
  прогрессом; ошибка — сообщение в модалке.
- Правка модалки = правка `imagerouter/devbim_topright_buttons.js` +
  повторный `setup_imagerouter.py` (виджет и так его деплоит) + F5.

### Сервер и деплой

- `threed/threed_router.py` → `routers/threed.py`: POST
  `/api/v1/threed/generate`, GET/PUT `/api/v1/threed/model`.
  Per-company: IFC-файлы в `get_config().root_path/ifc`, файл выбора
  модели в `root_path/data` (как imagerouter_upscale.json).
- `threed/scenarios.py`: системные промпты (EN, жёсткое «ответь ТОЛЬКО
  валидным JSON без markdown-заборов»), по одному компактному few-shot
  примеру на сценарий, извлечение JSON-блока из ответа,
  валидаторы+автопоправки схем.
- `threed/build_ifc.py`: три режима сборки + превью-PNG (matplotlib
  Agg, как скилл). Зависимости: `pip install ifcopenshell shapely`
  (cp311 wheels, общий venv на все компании).
- Вызов VLM — лениво через задеплоенный imagerouter-роутер (паттерн
  `prompt_enhancer.call_vlm`): единый источник ключа/базового URL;
  max_tokens 4000 (грабля п.22: reasoning-модели при малом лимите
  возвращают пустой content), temperature 0.2, use_cache=False.
- `setup_threed.py`: идемпотентный, бэкапы `*.threed-bak`, копирует
  роутер и модули, патчит `api_app.py` (после design_code-роутера;
  гейт: imagerouter-патчи применены). Порядок после force-reinstall:
  rebrand → imagerouter → ifcviewer → pdfviewer → designcode →
  **threed** → siteauth. Админ-секция менеджера — в imagerouter.html
  (деплой setup_imagerouter.py).

### Ошибки

- Модель из менеджера исчезла из каталога / каталог недоступен → 422
  «Модель 3D-анализа недоступна» + имя.
- Ключа ImageRouter нет → как у prompt_enhancer (ясная ошибка).
- Astra вернула не-JSON → 1 ретрай → 422 «Модель не смогла описать
  сцену…».
- Пустая сцена (0 зданий / 0 мебели) → 422 «На картинке не найдено
  объектов для 3D».
- Сборщик упал → 422 с пояснением (паттерн `_ir_error_body`).
  Диагностический дамп `data/_threed_last.json` (промпт, сырой ответ,
  распарсенная сцена, ошибки) — перезаписывается каждой генерацией.

## Что НЕ входит (кандидаты на продолжение)

- Tool-calling цикл (Astra вызывает наши инструменты сборщика, паттерн
  MCP4IFC без Blender) — этап 2, если качества одношотового JSON не
  хватит; `tools` через шлюз ImageRouter не проверен.
- Внешний image-to-3D меш-сервис (Meshy/Tripo) — если понадобится
  3D по ФОТО готового интерьера (вход сценария «Интерьер» — план;
  фото-вход осознанно не делаем).
- Локализация системных промптов (всегда EN — стабильнее для JSON).
- Пакетная генерация, история 3D-генераций (модели и так в списке IFC).

## Фазы

## Проверка

- `tests/test_threed.py`: схемы всех сценариев (валидный/невалидный
  JSON, автопоправки, clamp, выкидывание битых секций), сборщик
  (IFC4, уникальные GlobalId, замкнутость тел, объём = площадь ×
  высота, соответствие этажности — по образцу `test_model.py` скилла),

- Живой smoke: по одной генерации на сценарий (~$0.05–0.15: completion
  Astra $50/M, JSON 1–3k токенов).
- E2E (Playwright): генплан-картинка на холст → 3D → «Генплан» →
  промт «5-этажный жилой, школа 3 этажа» → модель в списке IFC и

  автозагрузка lastModel вне блока `if (EMBED)`; App-бандл не патчим
