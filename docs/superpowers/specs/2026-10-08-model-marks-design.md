# Спека: пометки моделей в списке генерации — звёзды 1–5 и мини-баннеры

Дата: 2026-10-08. Ветка: `user`.

## Контекст

Пользовательский список моделей генерации — инъекция мидлвари в
`GET /api/v2/models/` (`_ir_fake_config`): выбор админа
(`data/data/imagerouter_main_models.json`, порядок, первый — дефолт).
Опция дропдауна «Модель» (аккордеон «Генерация», ModelPicker `Sv` +
PickerItemComponent `Xte` в App-бандле) рендерит: имя, затем поля
конфига `file_size` и **`usage_info`** (серый суб-текст, всегда, даже
в компактном виде), ниже — `description`. Список моделей кладётся в
RTK-стор БЕЗ zod-преобразования (`getModelConfigs.transformResponse` =
entity adapter), т.е. `usage_info` доходит до UI как есть. Под
селектором уже есть блок описания выбранной модели
(`devbim_model_info.js` → `dist/devbim-model-info.js`).

Запрос пользователя (08.10): в списке моделей — «звёзды» 1–5 (сила
модели именно для редактирования), мини-баннеры для специальных
моделей (например вырезание фона), баннер «edit»; начальные значения
проставить самому, но настройки должны быть в менеджере моделей
(`imagerouter.html`), чтобы владелец менял их сам.

## Решение

1. **Хранение**: `data/data/imagerouter_model_marks.json` (per-company,
   как main-models): `{"badges": {ключ: {"label","color","title"}}}`,
   `"marks": {model_id: {"stars": 0..5, "badges": [ключи]}}}`.
2. **Дефолты в коде** (`_DEFAULT_BADGES`, `_DEFAULT_MARKS`) для
   известных моделей (выбор владельца на 08.10 + популярные редакторы
   каталога). Файл отсутствует → действуют дефолты; файл есть →
   действует ТОЛЬКО он (первое сохранение в менеджере фиксирует
   снапшот). Каталог баннеров: edit / bg (вырезание фона) / erase /
   fast + свои в JSON.
3. **Инъекция**: `_ir_fake_config` добавляет `usage_info` =
   `"★★★★☆ · EDIT · BG CUT"` (звёзды 1–5, «★»×n + «☆»×(5−n), затем
   метки баннеров через «·»). description НЕ трогаем — на нём стоит
   гейт Generate-фолбэка (слово «editing»).
4. **Эндпоинты**: `GET/PUT /api/v1/imagerouter/model-marks` (как
   main-models: PUT пишет файл; stars 0–5, badges из каталога,
   неизвестные id в marks переносятся как есть — модель может
   вернуться в каталог).
5. **UI под селектором и в дропдауне** (`devbim_model_info.js`):
   в блоке описания выбранной модели — строка звёзд (жёлтые ★) и
   цветные мини-баннеры (чипы с фоном цвета из каталога). В самом
   дропдауне usage_info — плоский текст (надёжно, без патчей бандла);
   скрипт дополнительно раскрашивает его: MutationObserver по
   поповеру пикера оборачивает метки баннеров в цветные чипы
   (best-effort, текст остаётся читаемым и без JS).
6. **Менеджер** (`imagerouter.html`): секция «Звёзды и баннеры
   моделей» — весь каталог с поиском, у каждой модели select звёзд
   0–5 и чекбоксы баннеров; редактор каталога баннеров (добавить
   метку+цвет, удалить неиспользуемый); сохранение PUT-ом.
   Предпросмотр строки usage_info.

## Не-цели

- Апскейл-дропдаун вкладки Upscaling (там свой пикер без usage_info) —
  пометки только в списке генерации/правки.
- Сортировка списка моделей по звёздам (порядок = выбор админа).
- Групповые операции над пометками.

## Грабли учтены

- zod `VJ` (диспетч выбора модели) вырезает лишние поля только из
  `params.model` — списку это не мешает, usage_info рендерится из стора.
- `usage_info` с `noOfLines:1` — строка держим короткой.
- Кириллица в файлах → `encoding="utf-8"`, `ensure_ascii=False`
  (как везде).
- React-дерево поповера не патчим структурно: только текстовые узлы
  своего формата, деструктивных конфликтов с reconciler нет
  (текстовые children не меняются после маунта опции).
