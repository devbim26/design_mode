# Спека: 3D Design — сценарий «Interior» (interior3d, рендер интерьера)

Дата: 2026-10-05. Ветка: `3d` (текущая `feature/studio-sso`).

## Проблема

Пользователь загружает РЕНДЕР/фото готового интерьера (перспектива, мебель,
люди) и хочет получить концептуальную 3D-модель комнаты с той же камерой,
что на исходнике. Существующие сценарии не подходят: `interior` (плитка
«Floor Plan») работает только с 2D-чертежом плана; `scene`/`facade` —
уличные мотивы. Ключевое требование: **камера вьювера после генерации стоит
как камера оригинального рендера** (глаз внутри комнаты, взгляд на цель).

## Решение — новый сценарий `interior3d` (плитка «Interior»)

Конвейер как у «Сцены» (фаза 4): фото → VLM → строгий JSON → валидатор →
сборка IFC + превью-план → camHint → вьювер ставит камеру.

### Контракт сцены (room-frame, метры)

Комната — ортогональный «боксовый» каркас (shoebox): центр комнаты в (0, 0)
на полу, X — восток (право), Y — север (вглубь, от зрителя), Z — вверх.
Южная стена (y = −d/2) — за спиной камеры рендера.

```
{
 "room": {"width_m": <X>, "depth_m": <Y>, "height_m": <>,
          "ceiling": <bool>, "floor_color": "#…", "ceiling_color": "#…"},
 "openings": [{"wall": "south|north|east|west", "x_m": <центр вдоль стены
   от её ЛЕВОГО конца, если смотреть ИЗНУТРИ комнаты>, "w_m", "h_m",
   "sill_m": <0 дверь, ~0.9 окно>, "kind": "door|window"}],
 "furniture": [{"type": "bed|sofa|armchair|table|chair|wardrobe|kitchen|
      tv|rug|plant|lamp|other", "x_m", "y_m", "w_m", "d_m", "h_m",
   "rot_deg": <0 = длинная сторона вдоль X>, "color": "#rrggbb" (опц.)}],
 "people": [{"x_m", "y_m", "h_m": <1.4-2.0, дефолт 1.7>, "rot_deg"}],
 "camera": {"eye_x_m", "eye_y_m", "eye_z_m": <1.0-2.0>, "yaw_deg":
   <0 = взгляд на север +Y; 90 = на восток +X>, "target_x_m",
   "target_y_m", "target_z_m": <куда смотрит камера>}
}
```

Стены красятся ПАЛИТРОЙ ОРИЕНТАЦИЙ (05.10, «не сливаться», как фаза 3):
юг/север — терракота, запад/восток — хаки (hex-ы INTERIOR_WALL_PALETTE
ext-вариантов — их узнаёт AI-палитра вьювера); `wall_color` из схемы
убран, VLM отдаёт только floor/ceiling_color.

Якоря масштаба: дверь 2.0–2.1 м, кровать 2.0×1.6, диван 2.2×0.9,
обеденный стол 1.4×0.8×0.75, стул 0.45×0.45×0.9, человек 1.7.
Камера ВСЕГДА внутри комнаты; VLM перечисляет каждый видимый предмет
и человека (в т.ч. частично перекрытые).

### Валидация (`validate_interior3d`)

- Гейт ValueError: не dict / нет `room` (нулевые/битые габариты — не гейт,
  а кламп, как в фасаде).
- Клампы: width 2–30, depth 2–30, height 2.0–6.0 (дефолты 5×4×2.7);
  openings: ширина 0.3–6, высота 0.5–3.2, sill 0–2, x_m посадка в длину
  стены с полями (кламп + warning), «door» с sill>0.3 → warning+0;
  furniture: размеры 0.05–6 / высота 0.02–3, позиция кламп в комнату
  (warning), лимит 80 предметов; people: h 1.2–2.2, лимит 20;
  camera: глаз кламп внутрь комнаты (отступ 0.3 от стен, warning),
  eye_z 0.5–2.5, target кламп в комнату ±2 м; цвета hex-гейт → дефолты.
- Возвращает `(scene, warnings)` — как `scene`/`facade` (контрактных
  issues-этапов нет; ансамбль/grounding для interior3d НЕ включаем —
  как у «Сцены»).

### Сборка (`build_interior3d`) — IFC4 + превью

- Пол IfcSlab CONCEPTUAL_FLOOR (w+0.3 × d+0.3 × 0.15, верх z=0);
  потолок IfcSlab CONCEPTUAL_CEILING при ceiling=true (z=h…h+0.12).
- 4 стены IfcWall CONCEPTUAL_WALL: юг/север длиной w+2t, запад/восток
  длиной d, толщина t=0.15, z=0…h. Имена «Стена южная» и т.д.
- Проёмы: IfcBuildingElementProxy CONCEPTUAL_DOOR/WINDOW — коробка
  w×0.12×h на ВНУТРЕННЕЙ грани стены (+0.06 в комнату — урок фазы 2
  про совпадающие грани), поворот по стороне света.
- Мебель IfcFurnishingElement FURNITURE_<TYPE>, палитра типов + hex из
  VLM (динамические стили), люди IfcBuildingElementProxy
  CONCEPTUAL_PERSON 0.5×0.3×h_m (паттерн «Сцены»).
- pset CameraHint на IfcProject: Mode="interior", EyeX/Y/ZM, YawDeg,
  TargetX/Y/ZM (метры IFC); pset RoomModel на IfcBuilding.
- Превью: план комнаты сверху (мебель, люди, маркер камеры-глаз +
  стрелка взгляда до target).

### Камера вьювера

`camHint` ответа: `{"mode": "interior", "eye": {x_m, y_m, z_m},
"target": {x_m, y_m, z_m}, "yaw_deg": …, "box": {"min": [x,y,z],
"max": [x,y,z]}}`. `box` — ТОЧНЫЙ IFC-бокс комнаты (x±(w/2+T),
y±(d/2+T), z∈[−0.15, h(+0.12 потолка)]): вьювер СДВИГАЕТ модель в мире
(трансляция запекается во фрагменты) и переводит глаз/цель/пол по
формуле T = worldBox.center − ifcBox.center (оси (x, z, −y)).

`applyCamHint()` в ifcviewer.html — ветка mode="interior" (05.10,
продолжение): (1) орбитальная цель = target рендера; (2) человек
ставится на пол у позиции глаза БЕЗ луча (`placePersonExact` —
snapToGround у стен промахивается, а пол известен из бокса);
(3) сразу `enterFP()` — «Вид от глаз» 1,7 м: камера жёстко на глазах
человека, взгляд точно по направлению оригинала, мышь — только осмотр,
WASD — ходьба, орбиты нет (камера не уходит за стены); ESC — орбита,
в ней виден силуэт человека. Подсказка персистентна по имени модели
(`devbim:ifc:interiorCam`): F5/повторное открытие возвращает вид
изнутри. Старые подсказки «Сцены» (azimuth_deg) не меняются.

### Роутер

`SCENARIOS += interior3d`; диспетчер system/валидатора/сборщика;
в `_run_attempt` для interior3d — `res_i["camHint"]` из `scene["camera"]`
(преобразование в hint-формат). Ансамбль — мимо (список
`("facade", "plan", "interior")` не трогаем). verify: ветка
`scene_overview` для interior3d (камера/комната/проёмы/мебель/люди);
оверлей-этап — без ветки (как у «Сцены», судья видит только оригинал).

### Фронтенд

4-я плитка «Interior» (🛋, data-s="interior3d") в модалке 3D Design;
«Floor Plan» получает 📐; placeholder RU/EN по сценарию. Ключ
`interior3d` в TEXTS/`ph`-карте. Имя файла `3D_interior3d_<stamp>.ifc`.

## Границы (не делаем)

- Не трогаем сценарий `interior` (Floor Plan) и его конвейер.
- Без ансамбля/grounding/ремонта (B-прогон с боксами для перспективного
  рендера комнаты — отдельная тема, если понадобится).
- Стены только ортогональные (shoebox); скошенные/эркерные комнаты —
  приближение боксом с warning в pset.
- Людей не анимируем и не ставим реальную сканированную фигуру —
  схематичный бокс, как в «Сцене».

## Риски

1. VLM перепутает стену-носитель проёма (юг/север) — есть клампы и
   предупреждения; verify-петля ловит расхождения.
2. Камера за пределами комнаты у VLM — кламп внутрь с warning; вьювер
   получает только валидированный hint.
3. Мебель внахлёст со стенами — позиционный кламп в габарит комнаты;
   пересечения мебели между собой НЕ решаем (концептуальная модель,
   фикс в pset ApproximateGeometry).
