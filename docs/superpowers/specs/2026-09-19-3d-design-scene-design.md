# Спека 2: 3D Design — фиксы фасада + сценарий «Сцена» (camera mapping)

Дата: 2026-09-19 · Ветка: `3d` · Предыдущая: `2026-09-19-camera-mapping-probe-design.md` (зонд: гипотеза подтверждена)

## Контекст и цель

Зонд подтвердил: edit-модель (google/nano-banana) способна перенести камеру
с 3D-прокси и материалы с фото, если камера прокси стартует в точке съёмки
фото и вращается в зоне ~±20–30°. Теперь строим продакшн-конвейер:

1. **Этап A — фиксы фасада** (диагностированы при разборе жалобы 19.09):
   балконы за габаритом, дефолтная камера показывает глухой тыл.
2. **Этап B — сценарий «Сцена»**: по одному фото улицы — грубая 3D-сцена
   из примитивов (1–3 здания, деревья, машины, люди, земля) + оценка камеры
   фото. Это заготовка для «здания под новым углом» (рендер — спека 3).

Интерьер (фаза 3) реализован параллельной сессией 19.09 (HANDOFF п.40):
плитка активна, роутер принимает interior. «Сцена» добавляется ЧЕТВЁРТЫМ
сценарием и код интерьера не трогает (в репозитории параллельно идут
другие сессии — коммитить только свои файлы, перечитывать файлы перед
правкой).

## Этап A: фиксы фасада (TDD)

A1. **Балконы в габарит** — `threed/threed_build.py` (build_facade):
    `cx = bal["x_m"] - data["width_m"] / 2` (семантика x_m — «от левого
    края», как в SYSTEM_FACADE). Сейчас cx = x_m без сдвига → балконы
    висят в воздухе справа от здания (жалоба пользователя, доказано
    геометрией IFC 18:41/18:53).
A2. **Валидатор** — `threed/threed_scenarios.py` (validate_facade):
    плита балкона обязана влезать целиком: `x_m ± w_b/2` в `[0, width_m]`;
    нарушение — кламп x_m в `[w_b/2, width_m − w_b/2]` с warning
    (дроп только если w_b > width_m). Балконы сохраняем: VLM их увидела.
A3. **Превью** — рисовалка фасада в build_facade: балконы по
    `x_m − w/2` (мировой фрейм чертежа), как окна. Сейчас смешение систем.
A4. **Окна на камеру** — фасадная грань с окнами переносится с IFC +Y
    на IFC −Y (окна cy=−d/2, балконы cy=−(d/2+d_b/2), фронт-офсет 0.06 м
    и матрица двускатной крыши — с обратным знаком). Причина: мировой
    трансформ вьювера (ifc −Y → world +Z, доказано зондом: world_z =
    −6 − ifc_y) разворачивает здание так, что дефолтная камера fitModel
    (диагональ +X+Z) сейчас видит глухой тыл — жалоба «параллелепипед
    без окон».
A5. Тесты (`tests/test_threed.py`, plain asserts): балкон в габарите
    (bbox по ifcopenshell), кламп в валидаторе, окна на −Y. Порядок:
    тесты падают → фикс → `setup_threed.py` → тесты зелёные (грабля
    п.38.5: тесты импортируют venv-копии).

## Этап B: сценарий «Сцена»

B1. **Модалка** (`imagerouter/devbim_topright_buttons.js`): плитка
    «Сцена» добавляется к активным Генплан/Фасад/Интерьер, placeholder
    промта RU/EN (promptPhScene) — «что видно на фото: здания, этажность,
    окружение; чем точнее опишете, тем точнее сцена».
B2. **SYSTEM_SCENE + схема JSON** (`threed_scenarios.py`):
    ```
    camera: {azimuth_deg: <±90; 0 = фронтально на главный фасад,
              + = камера справа от нормали>, eye_height_m, dist_m}
    buildings: [1..3] × {main: bool, x_m, y_m: <центр в плане, метры;
      оси плана = осям IFC X/Y, фронт — сторона −Y>,
      width_m, depth_m, storeys, floor_height, roof, windows{rows, cols,
      w_m, h_m, margin_x_m, margin_y_m}, balconies[], colors}
    context: {trees: [{x_m, y_m, h_m, crown_d_m}], cars: [{x_m, y_m,
      rot_deg}], people: [{x_m, y_m}]}
    ```
    VLM-якоря масштаба как в фасаде (этаж 3 м, машина 4.5×1.8, дерево
    5–8 м, человек 1.7). Правило: боковые стены главного здания получают
    упрощённую сетку окон — side_cols = clamp(round((depth_m − 1.6) /
    шаг_фронта), 1, 6), размеры/отступы как у фронта: глухие боковины
    рендер не достраивает (вывод зонда №3).
B3. **validate_scene**: диапазоны/дефолты по образцу validate_facade;
    битые элементы контекста — drop с warnings; camera — клампы
    (azimuth ±75°, height 0.3–30 м, dist 10–200 м).
B4. **build_scene** (`threed_build.py`): переиспользует box()-механику
    фасада: здания (тома-этажи + окна на передней и боковых гранях +
    балконы + цоколь), деревья (ствол-бокс + крона-бокс), машины (боксы
    4.5×1.8×1.4 + rot), люди (боксы 0.5×0.3×1.7), земля — плита.
    pset SceneModel на IfcBuilding (состав сцены) + pset CameraHint на
    IfcProject (azimuth/height/dist — для спеки 3 и отладки).
    Главный фасад — на IFC −Y (дефолтная камера видит его, A4).
    Ориентация сцены: главное здание в (0,0), azimuth камеры задаёт
    только CameraHint (камеру ставит вьювер/пользователь — этап B6).
B5. **Превью**: план сцены сверху (здания + контекст + маркер камеры
    с направлением) — пользователь видит композицию до 3D.
B6. **Камера вьювера после генерации**: виджет кладёт в localStorage
    `devbim:ifc:camHint` = JSON {azimuth_deg, eye_height_m, dist_m};
    `ifc/ifcviewer.html` после загрузки модели, если подсказка есть,
    ставит камеру сам (грань главного фасада — сторона +Z мира, см. A4)
    вместо fitModel; подсказка одноразовая (removeItem).
    Деплой — `setup_ifcviewer.py` (патч — идемпотентно, маркер-комментарий).
B7. **Роутер**: SCENARIOS += "scene"; ветвление промпт/валидатор/сборщик;
    имя файла `3D_scene_<stamp>.ifc`.
B8. **Тесты**: валидатор (клампы/дропы), сборщик (bbox зданий/контекста,
    окна на трёх гранях главного, CameraHint в pset), роутер (сценарий
    в списке), модалка (плитка/placeholder), вьювер (наличие обработки
    camHint в ifcviewer.html).

## Вне объёма

- Рендер с референсом в ИИ-рендере канваса + выбор edit-модели — спека 3.
- Интерьер, N картинок на входе (после спеки 3), точная фотограмметрия.

## Критерии приёмки

- Фасад: балконы внутри габарита на превью и в IFC; дефолтная камера
  вьювера показывает фасад с окнами (E2E: тёмные пиксели остекления > 5%
  с дефолтного ракурса).
- Сцена: по фото улицы — IFC с 1–3 зданиями, контекстом-примитивами,
  превью-планом; камера вьювера после генерации стоит по CameraHint
  (фронтально-сбоку, уровень глаза из JSON); warnings видны в модалке.
- Все тесты `tests/test_threed.py` зелёные; порядок деплоя из AGENTS.md.

## Риски

- Трансформ loader'а (@thatopen) для сцен из нескольких зданий: A4/B4
  опираются на устойчивое соответствие ifc −Y → world +Z; проверяется
  E2E в приёмке; запасной вариант — camHint в мировых координатах,
    вычисляемых вьювером по bbox (только сторона +Z).
- VLM-переоценка azimuth (зонд: −45° на глаз) — CameraHint клампится,
  пользователь всё равно докручивает камеру руками.
