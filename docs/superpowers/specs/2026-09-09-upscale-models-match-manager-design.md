# 2026-09-09 — Upscaling: модели как в менеджере + поля размеров/качества

Запрос пользователя: «в апскейлинг приходят не те модели что в менеджере..
надо поля где видно размеры.. длина ширина и качество 1 234 К».

Диагноз: дропдаун «Модель увеличения» показывает 5 дефолтных спец-апскейлеров
(DEFAULT_UPSCALE_MODELS, зашиты в код, файл выбора не создавался), а в менеджере
«модели пользователя» — сохранённый выбор секции «Генерация и правка»
(14 моделей). Все 14 поддерживают вход-image и пригодны для апскейла
(edits-запрос). Решение пользователя: дропдаун повторяет выбор менеджера.

## 1. Наследование выбора (сервер, imagerouter_router.py)

Цепочка источников для spandrel-инъекции / upscale-options / GET
/api/v1/imagerouter/upscale-models:

1. `data/imagerouter_upscale.json` существует — сохранённый выбор (как раньше;
   пустой список = отключить апскейл);
2. файла нет, есть `data/imagerouter_main_models.json` — наследуем его список
   («модели в апскейлинге = модели в менеджере»);
3. нет обоих — DEFAULT_UPSCALE_MODELS (дефолт для свежих установок).

GET /upscale-models дополнительно отдаёт `selection_source`
(`file` / `main` / `default`) и флаг `inherited_from_main`; `defaults_used`
оставлен (True только для ветки 3). Инъекция по-прежнему фильтрует список по
каталогу и вход-image — все модели менеджера с ✏️ правкой проходят.

Админ-UI (imagerouter.html, секция «Апскейлинг»): при inherited_from_main
подсказка «Показан выбор из секции „Генерация и правка" — сохраните, чтобы
закрепить отдельный список». Чекбоксы отражают эффективный список.

## 2. Поля «Ширина / Высота / Качество» (панель вкладки, setup_imagerouter.py)

В компонент Yae (замена слайдера, v1 от 09.09 утро) добавлен блок из трёх
полей только для чтения над «Режимом увеличения» — по текущему изображению
вкладки (ImageDTO из стейта `qE`):

- **Ширина** — `img.width` px;
- **Высота** — `img.height` px;
- **Качество** — размер файла оригинала в КБ: HEAD-запрос по `img.image_url`,
  Content-Length → `Math.round(bytes/1024)` с русским разделителем тысяч
  (1 234 К). ImageRecord не несёт file_size — потому HEAD.

Без изображения — «—», пока HEAD в полёте — «…». Компонент пишет
`window.__devbimUpscaleImgInfo={width,height}` (отладка E2E, как __devbimUpscaleMode).

Идемпотентность патча: маркер v2 — `__devbimUpscaleImgInfo`; бандл с v1
(маркер `window.__devbimUpscaleMode` без v2) перепатчивается v1→v2 (остальные
три замены панели уже применены — пропускаются), свежий бандл — все четыре
замены сразу OLD→v2. Бэкап бандла не перезатирается.
