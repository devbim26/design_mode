# Дизайн: «Текст» (T) — текстовый слой на холсте InvokeAI

Дата: 10.09.2026. Запрос пользователя: «на холсте добавь новый тип слоя —
текстовый… я пишу текст, он формируется на отдельном слое… далее я этот
текст могу поменять цвет… и размер изменением размеров слоя или вводя
размер шрифта… сам реши как удобно».

## Решение (что удобно)

Отдельный ТИП сущности канваса (в духе «text layer» Figma) в собранном
бандле 6.2 не создать — state-слайс, Konva-рендер и персистентность
минифицированы. Поэтому текстовый слой = **растровый слой с одним
объектом-картинкой** (id объекта `image_devbimtext_*`), который виджет
создаёт/перерисовывает. Слой ведёт себя как обычный растровый: двигается
(V), масштабируется штатным bbox (B), участвует в генерации. Параметры
текста (содержимое, цвет, размер шрифта, гарнитура, жирность) живут в
реестре localStorage — слой остаётся ПЕРЕ-РЕДАКТИРУЕМЫМ после создания.

Размер меняется двумя способами (оба работают одновременно):
- **вводом размера шрифта** в панели (px) → перерисовка текста;
- «изменением размеров слоя» → штатный bbox-инструмент (B): после
  масштабирования слой растеризуется приложением (штатный механизм),
  объект получает новый id, но id СЛОЯ сохраняется — реестр ключуется по
  id слоя, связь не теряется; следующая правка перерисует текст заново.

## Состав

- **Кнопка T** в вертикальной рейке инструментов холста (иконка «type»,
  1em; рейка ищется по aria-label «(B)»+«(E)» — как у ✂). Пересоздаётся
  тиком 500 мс (ремоунт рейки), убирается вне холста.
- **Панель** (fixed, bottom:142px — над пилюлей Mask/Layer на 96px):
  textarea (многострочно), color-picker + hex-поле, размер шрифта
  (число 8–512 px), гарнитура (Sans/Serif/Mono), «Ж», кнопки
  «Добавить»/«Применить» и ✕. Esc — закрыть, Ctrl+Enter — применить.
  Язык RU/EN по navigator.language.
- **Живое превью** (только для НОВОГО текста): div-оверлей
  (pointer-events:none, rAF-синхронизация) в центре видимой области
  канваса — текст в выбранном цвете/размере×зум, пунктирная рамка.
  При правке существующего слоя превью отключено (под ним реальный
  объект; измения видны по «Применить»).
- **Реестр**: localStorage `devbimTextLayers` → `{[layerId]:
  {text,color,size,family,bold}}` (ключ = id СЛОЯ — переживает и F5,
  и bbox-растеризацию; объектный id при растеризацией приложения
  меняется, слой — нет).

## Логика

### «Добавить»
1. Рендер текста: offscreen-canvas, шрифт `${bold?"bold ":""}${size}px
   ${family}`, межстрочный 1.25, отступ max(2, 12% размера), перенос
   строк по \n; ширина = самая длинная строка. Konva показывает картинку
   объекта в НАТУРАЛЬНОМ размере (`image.width/height` из DTO — поля
   width/height самого объекта рендером игнорируются), поэтому растр
   рендерится точно в документных пикселях 1:1.
2. `POST /api/v1/images/upload?image_category=other&is_intermediate=
   true&silent=true` (параметры в QUERY — грабля 6.2, как у ✂).
3. `stateApi.addRasterLayer({isSelected:false, overrides:{objects:
   [{id:"image_devbimtext_*",type:"image",image:{image_name,width,
   height}}], position, name}})` — путь sentImageToCanvas: объекты и
   позиция передаются overrides ОДНИМ диспатчем (Wi = deepmerge);
   isSelected:false — без рамки выделения (решение по ✂-фидбеку).
   Position — центр видимой области канваса в координатах документа
   (минус половина блока, clamp в границы документа), задаёт «где я
   смотрю — там и текст».
4. Реестр[layerId] = настройки; toast.

### «Применить» (правка)
Слой опознаётся так: выделенная сущность raster_layer и id есть в
реестре (подписка на store — панель перезаряжается при смене выделения).
1. Перерендер текста + upload (как выше).
2. `canvas/entityRasterized` (raw-диспетч, как у ✂): replaceObjects:
   true, position = прежняя position слоя, isSelected:false, наш
   объектный id.
3. `canvas/entityNameChanged` — имя слоя синхронизируется с текстом
   (`T · первая строка ≤24 симв.`); диспатчи одного тика = один шаг undo.

### Перетаскивание
Плавный драг (сетка позиций 64 px → 1 px, пока тащат НАШ слой): обёртка
`getPositionGridSize` с собственным флагом `__devbimTextSmooth` —
цепочится после ✂-обёртки (`__devbimSmooth`), не конфликтуя. Наши слои:
id в реестре ИЛИ объект с префиксом `image_devbimtext_`.

## Деплой и отладка

Виджет `imagerouter/devbim_text_tool.js` → `dist/devbim-text-tool.js` +
script в index.html (новая `deploy_text_tool()` в setup_imagerouter.py,
бэкап `index.html.texttool-bak`, идемпотентно). Бандлы НЕ трогаются,
перезапуск сервера не нужен — только F5. Отладка: `window.__devbimText`
(state/add/apply/registry). Тесты: `tests/test_text_tool.py`.

## Что сознательно НЕ делаем (YAGNI)

- Свой тип entity / Konva-нод текста — невозможно в минифицированном
  бандле, растр закрывает 100% сценария (генерация, bbox, undo).
- Клик-размещение текста по точке канваса — центр видимой области + V
  проще и предсказуемее.
- Выравнивание строк, курсив, обводка/тень текста — добавить при
  запросе (одно поле в рендере + реестр).

## Грабли (пойманы E2E 10.09)

- **Кэш абсолютного трансформа stage бывает отравлен NaN**: attrs
  чистые (scale/position валидны), но `getAbsoluteTransform()` (кэш!)
  возвращает NaN — лечится только РЕАЛЬНЫМ изменением атрибута
  (повторный `scaleX(то же)` шорткатится Konva без dirty). Поэтому
  виджет НИКОГДА не читает этот кэш: координаты doc↔screen считаются
  по атрибутам `stage.scaleX()/x()/y()` (зум приложения = scale +
  position, без поворота) + `isFinite`-защита с фолбэком в центр
  документа. Это же причина грабли ✂ (toDoc через invert) — не тронуто.
- **Панель (fixed, низ-центр) перекрывает канвас**: мышь над панелью
  уходит в неё, Konva событий не получает — перед перетаскиванием
  слоя панель закрыть (Esc). Превью — pointer-events:none.
- Синтетические `stage.setPointersPositions({x,y})` без clientX/clientY
  дают NaN в `getPointerPosition()` → `getIntersection` падает на
  getImageData — артефакт тестов, не баг приложения.

## E2E (10.09, Playwright + живой сервер)

Создание (96px, #38BDF8, жирный): слой `T · DevBIM 2026`, растр 630×144
ровно по метрикам, позиция = центр видимой области, 4765 голубых
пикселей в растре, консоль чистая. Правка (48px, #ff3333, тонкий,
текст «DevBIM 2026!»): entityRasterized + entityNameChanged, позиция
сохранена, новый растр 308×72, 1153 красных пикселя, реестр обновлён;
панель сама вошла в режим правки при выделении слоя (store.subscribe).
Драг «Двигать (V)»: (198,384) → (542,214) — дельта +344/−170 doc при
экранной +72/−37 (зум 0.212), НЕ кратно сетке 64 (обёртка
`__devbimTextSmooth` цепочкой после ✂; обычные слои — по-прежнему 64).
F5: слой/имя/позиция/объект/реестр/кнопка пережили перезагрузку,
панель вошла в правку выделенного слоя. Скриншоты:
