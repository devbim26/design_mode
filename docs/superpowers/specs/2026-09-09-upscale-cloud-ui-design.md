# 2026-09-09 — Upscaling: чистка локальных пунктов + режимы и форматы из облака

Запрос пользователя: во вкладке апскейлинга есть пункты меню, актуальные
только для локальной разработки — убрать и адаптировать под облачные
модели. Система должна знать доступные режимы апскейла (2×, 4K, …) и
форматы изображения, подтягивать их автоматически для выбранной модели,
пользователь — только выбирать.

## Что убираем (локальный пайплайн, граф всё равно перехватывается мидлварью)

Левая панель вкладки Upscaling (бандл `App-*.js`):

1. Аккордеон «Генерация» (`Wae` / UpscaleTabGenerationSettingsAccordion):
   main-модель, LoRA, планировщик, шаги, CFG — параметры локальной
   SD-панайплайна. Мейн-модель остаётся в стейте (автоселект фейка sdxl)
   — граф без неё не строится, но UI её больше не показывает.
2. Аккордеон «Опции Расширенные» (`Uae`): VAE, precision, clip-skip,
   seamless, seed — то же.
3. Внутри аккордеона «Увеличить» (`Qae`):
   - блок main-модели + tile-ControlNet (`_Ke`) — локальная tiled-диффузия;
   - «Advanced Options» со слайдерами Creativity/Structure (`pKe`/`bKe`)
     и tile-параметрами — управление локальной диффузией; серверный промпт
     теперь фиксируется режимом, ручки убираем;
   - слайдер «Масштаб» 2–8× (`Yae`) — вводит в заблуждение: облачные
     апскейлеры honour только собственный множитель (−2x-модели дают
     ровно ×2 при любом scale).

## Что добавляем

Вместо слайдера «Масштаб» — два селектора (новый `Yae`):

- **«Режим увеличения»** — режимы выбранной модели из нового эндпоинта;
- **«Формат изображения»** — png / jpeg / webp (глобальный параметр
  ImageRouter edits-запроса `output_format`; по умолчанию png — без потерь,
  выбор персистится в localStorage).

Данные режимов/форматов доставляет `GET /api/v1/imagerouter/upscale-options`
(только модели из выбора администратора — тот же фильтр, что инъектирует
spandrel-фейки, чтобы списки совпадали один-в-один):

```json
{"models": [{
  "id": "csslc/ccsr-2x", "name": "ccsr-2x",
  "modes":  [{"id": "2x", "label": "2×", "scale": 2}],
  "formats": ["png", "jpeg", "webp"], "default_format": "png"
}, {
  "id": "prunaai/P-Image-Upscale",
  "modes":  [{"id": "2048x2048", "label": "2048×2048", "size": "2048x2048"},
             {"id": "2896x2896", "label": "2896×2896", "size": "2896x2896"}],
  ...
}]}
```

Вывод режимов из каталога (`parameters.size`):
- явные размеры → режим-на-размер (точный `size` в запросе);
- суффикс id `…-<n>x` → единственный режим `<n>×` (множитель честный);
- прочий `custom` → фолбэк `2×` и `4×` (запрос size honoring, кап 2048).

## Передача выбора на сервер

Билдер графа вкладки (`sSe`) патчится: spandrel-узел дополнительно несёт
`upscale_mode` и `output_format` из window-глобалов, которые выставляет
новый компонент селекторов (undefined → поля исчезают из JSON — quick-action
из контекстного меню не затронут, работает по-старому: scale=2, формат png).

`_extract_ir_info` вычитывает оба поля; `_handle_upscale_generation`:
- режим с `size` → точный размер запроса, множитель для промпта считаем
  от входа;
- режим со `scale` → множитель из режима (перекрывает слайдерный scale);
- без режима — прежнее поведение (совместимость);
- `output_format` валидируется по белому списку и уходит в edits-тело.
Промпт `_upscale_prompt` говорит «approximately <режим>» (2× или размер).
