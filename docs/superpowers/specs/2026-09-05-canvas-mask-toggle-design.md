# Спека: тумблер «Маска / Слой» на холсте

Дата: 2026-09-05. Статус: одобрен пользователем (устно, после презентации
дизайна). Ветка: `feature/ifc-viewer`.

## Проблема

Кисть на холсте рисует то полосатой маской (слой Inpaint Mask), то цветом
(растровый слой) — зависит от того, какой слой выделен. Выделение меняется
незаметно для пользователя (в частности, кнопка «На холст» из IFC-вьювера
сама создаёт и выделяет слой маски и включает кисть — п. 13 HANDOFF).
В списке слоёв это видно плохо, пользователь путается.

## Решение (одобренный UX)

Плавающая «пилюля» с двумя кнопками над нижней панелью холста:

- **Маска** — подсвечена, когда выделен слой `inpaint_mask` (кисть рисует
  полосатой маской для правки).
- **Слой** — подсвечена, когда выделен `raster_layer` (кисть рисует цветом).
- Выделено иное (control-слой, регион) или ничего — обе кнопки неактивны.

Клик «Маска»: если маски есть — выделить самую свежую (последний элемент
`inpaintMasks.entities`); если нет — создать (`addInpaintMask` с
`isSelected`) и она выделится. Клик «Слой» — аналогично для растрового слоя.

Пилюля видна только на вкладке Canvas. Подписи русские: «Маска» / «Слой»;
title-подсказки: «Рисовать маской для правки (полосатая кисть)» /
«Рисовать цветом по картинке». Конкретный слой при необходимости по-прежнему
выбирается в панели слоёв — тумблер её дублирует, не заменяет.

## Архитектура

Схема «мост в бандле + отдельный скрипт» (как баннер/админ-окно DevBIM):

1. **Мост в App-бандле** — `patch_canvas_bridge()` в `setup_imagerouter.py`.
   В файл `assets/App-*.js` (тот, где `displayName="TabContent"`;
   сейчас `App-B3eY4dpl.js`) перед якорем `const cue=u.memo(` вставляется
   одна строка на уровне модуля:

   ```js
   window.__devbimCanvasBridge={getManager:()=>ru.get()};
   ```

   `ru` — модульная переменная бандла (стор менеджера канваса, `ru=De(null)`).
   Якорь после вставки сохраняется (вставка префиксом), поэтому патч
   IFC-вьювера (`setup_ifcviewer.py`, тот же якорь) продолжает находить его
   при любом порядке запуска скриптов. Идемпотентность: если в бандле уже
   есть сигнатура `__devbimCanvasBridge` — пропуск. Бэкап общий
   `*.imagerouter-bak`.

2. **Виджет** — новый исходник `imagerouter/devbim_mask_toggle.js`, деплой
   `deploy_mask_toggle()` в `setup_imagerouter.py`: копия в
   `dist/devbim-mask-toggle.js` + `<script defer src="/devbim-mask-toggle.js">`
   в `index.html` (идемпотентно, бэкап `index.html.masktoggle-bak`).

Правка вёрстки/стиля после деплоя — редактированием
`imagerouter/devbim_mask_toggle.js` + повторный запуск `setup_imagerouter.py`
(как баннер в `rebrand_devbim.py`), без пересборки бандлов.

## Data flow виджета

- Ожидание готовности: опрос 500 мс, пока есть `window.__devbimCanvasBridge`
  и `window.__devbimGetTab` (последний уже существует от админ-гейта).
- Менеджер: `const mgr = window.__devbimCanvasBridge.getManager()`; стор —
  `mgr.stateApi.store` (свойство `store` confirmed: `this.store=t` в
  конструкторе stateApi; настоящий redux-стор с
  `getState/dispatch/subscribe`).
- Обновление подсветки: `store.subscribe(...)` — читает
  `state.canvas.selectedEntityIdentifier` и ставит активной кнопку по
  `.type` (`"inpaint_mask"` / `"raster_layer"`). Работает и когда слой
  меняет IFC-мост «На холст», и кликом в панели слоёв.
- Health-check: раз в 1 с проверять, что `getManager()` возвращает тот же
  менеджер; если пересоздан — переподписаться.
- Видимость: опрос `window.__devbimGetTab() === "canvas"` (интервал того же
  тика 1 с; скрытие мгновенное не требуется).

## Действия кликов (сверено с бандлом 6.2.0)

- Выделить существующий слой:

  ```js
  store.dispatch({type:"canvas/entitySelected",
                  payload:{entityIdentifier:{id, type}}})
  ```

  Слайс `name:"canvas"`; редьюсер `entitySelected` берёт
  `t.payload.entityIdentifier` и проверяет существование сущности.
- Создать слой (готовые методы менеджера, диспатчат действия с prepare —
  id и мержинг корректны):
  - `mgr.stateApi.addInpaintMask({isSelected:true})`
  - `mgr.stateApi.addRasterLayer({isSelected:true})`
- Списки слоёв: `state.canvas.inpaintMasks.entities`,
  `state.canvas.rasterLayers.entities` (форма состояния сверена:
  `{selectedEntityIdentifier, inpaintMasks:{isHidden,entities[]}, …}`).

## Позиция и стиль

- `position:fixed; bottom:96px; left:50%; transform:translateX(-50%);
  z-index:1400` — над bbox-панелью по центру, не перекрывает её.
- Тёмная тема InvokeAI: фон `#0B0C0E`, рамка 1px `rgba(255,255,255,.08)`,
  радиус 999px; активная кнопка — акцент `#38BDF8` (цвет «BIM» в брендинге
  DevBIM). Иконки inline-SVG: маска — кружок со штрихами, слой — квадрат.
- Пилюля не перехватывает клавиатуру; pointer-events только на себе.

## Крайние случаи

- Менеджер не создан (пользователь не заходил на холст) — виджет скрыт.
- Несколько масок — выделяется последняя созданная; тонкая настройка через
  панель слоёв.
- `pip install --force-reinstall invokeai==6.2.0` — восстановление
  перезапуском `setup_imagerouter.py` (общее правило проекта).

## Тесты и проверка

- Новый `tests/test_mask_toggle.py` (plain asserts, печать OK):
  - деплой идемпотентен: двойной `deploy_mask_toggle()` не дублирует
    script-тег в `index.html` и файл в `dist/`;
  - `node --check` для `dist/devbim-mask-toggle.js`.
- Ручная проверка после изменений (дополнение к чек-листу HANDOFF):
  1. `node -e "import('file:///...App-*.js').catch(e=>console.log(e.message))"`
     — только `document is not defined`, не SyntaxError;
  2. перезапуск `_restart_server.ps1`;
  3. UI: на холсте видна пилюля; клик «Маска» — подсветка + кисть рисует
     полосками; клик «Слой» — кисть рисует цветом; «На холст» из IFC —
     подсветка сама переключается на «Маска»;
  4. F5 — подсветка соответствует сохранённому выделению;
  5. вкладка Generate — пилюля скрыта.

удалить `dist/devbim-mask-toggle.js`; перезапустить сервер.

## Не входит (out of scope)

- Перетаскивание пилюли, настройка позиции пользователем.
- Мультиязычность подписей (как у баннера) — подписи фиксированно русские.
- Управление видимостью слоёв, переименование, удаление — только выбор.
