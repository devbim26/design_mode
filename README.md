## Компании (лицензии)

Продажа по компаниям: каждой компании — отдельный экземпляр сервера со своим
портом, паролем и данными (галерея, IFC-файлы изолированы автоматически).

| Действие | Команда |
|---|---|
| Создать компанию | `python create_company.py --name "ООО «А»" --code acme --valid-until 2027-09-05` |
| Запустить | `start_company.bat acme` |
| Остановить | `python stop_company.py acme` |
| Список | `python list_companies.py` |
| Сменить пароль | правка `companies/acme/.env` (SITE_PASSWORD), перезапуск не нужен |
| Продлить лицензию | правка `SITE_VALID_UNTIL` в `companies/acme/.env` |
| Отозвать немедленно | `python stop_company.py acme` + смена SITE_PASSWORD |

Пароли выдаются в `companies/<код>/CREDENTIALS.txt` (в git не входит).
Адрес компании: `http://<сервер>:<порт>` (порт из `companies.json`).
Все экземпляры используют общий патченный venv; после переустановки InvokeAI
повторить патчи один раз (см. «Проверка после изменений» в HANDOFF.md).

### Изоляция данных компании

Каждый экземпляр работает со своим корнем `companies/<код>/data`, поэтому
изолируются автоматически (без отдельных настроек):

- **Галерея сгенерированных картинок** — в корне компании; базовый
  экземпляр 9090 и другие компании её не видят.
- **IFC-модели** — в `companies/<код>/data/ifc/` (роутер кладёт файлы в
  `<INVOKEAI_ROOT>/ifc`); каталог создаётся сам при первой загрузке, новая
  компания стартует с пустым списком. Перенести готовые модели (например,
  демо-набор из `data/ifc/` базового экземпляра) — просто скопировать файлы
  в папку компании, перезапуск не нужен. Лимит 500 МБ на файл действует в
  каждой компании независимо.
- **Доступ** — все эндпоинты (включая `/api/v1/ifc/*` и картинки) закрыты
  мидлварью входа: без пароля компании файлы недоступны и по прямому URL.

### Срок лицензии и отзыв

- `SITE_VALID_UNTIL=ГГГГ-ММ-ДД` в `.env` компании: после этой даты любой
  запрос (включая вебсокеты и попытку входа с верным паролем) закрывается
  страницей «Лицензия истекла» с контактом devbim. Дата входит в токен
  куки — её смена мгновенно инвалидирует выданные куки.
- `SITE_PASSWORD`/`SITE_VALID_UNTIL` перечитываются из `.env` на каждом
  запросе: смена пароля, продление и «мягкий» отзыв работают **без
  перезапуска сервера**. Немедленный отзыв — `stop_company.py` + смена
  пароля.
- Лог экземпляра: `companies/<код>/server.log` (пишет start_company.bat).

## Многопользовательский режим «users» (один экземпляр, публичный адрес)

Альтернатива компаниям: один сервер открывается наружу через туннель,
люди входят по почте и паролю, у каждого свой ключ ImageRouter и свои
рабочие файлы (`data/ifc|pdf/<почта>/`, картинки — по владению).
Полное руководство: **`docs/MULTIUSER.md`**.
Перенос системы на другой сервер: **`docs/MIGRATION.md`**.

| Действие | Команда / где |
|---|---|
| Включить/выключить | `.env` корня: `STUDIO_AUTH_MODE=users` + перезапуск `launch\_restart_server.ps1` |
| Вход владельца | страница входа: пустая почта + `SITE_PASSWORD` → `/admin` |
| Создать пользователя | `/admin` (форма) или `python user_manager.py add <email> [--password …] [--token sk-…]` |
| Пароли/токены/роли/блокировка | `/admin` или `user_manager.py set-password / set-token / role / revoke / restore` |
| Тесты | `tests\test_userauth_*.py` (store/login/admin/cli/token/files/threed) |

## Запуск

Все скрипты запуска системы собраны в папке `launch/` (краткий гайд для
человека — `launch/START-HERE.txt`, открывается двойным кликом).

### Главный способ — `launch\start-system-design.bat` (весь стек, двойной клик)

Поднимает **бэкенд (:9090) + туннель design.dev-bim.com** и не делает ничего
лишнего: если что-то уже работает — пропускает этот шаг (батник можно
запускать сколько угодно раз, дублей не плодит). Бэкенд стартует отсоединённо
(WMI, окно закрывать не нужно, лог — `ir_server.log` в корне), туннель — в
отдельном окне.

### Карта батников (все — в папке `launch\`)

| Батник | Что делает | Когда использовать |
|---|---|---|
| `launch\start-system-design.bat` | Бэкенд (если не работает) + туннель (если не работает) | **Обычный запуск** стека |
| `launch\open_frontend.bat` | Открыть UI в браузере (сервер выключен — сначала включит) | Просто поработать в программе |
| `launch\stop-system-design.bat` | Останавливает бэкенд :9090 и туннель design (дубли тоже; соседние туннели не трогает) | Остановить всё |
| `launch\status-design.bat` | Только проверка: порт, HTTP бэкенда, процесс туннеля, публичный URL | «Что-то не работает» — запустить первым |
| `launch\start_server.bat` | Принудительный перезапуск бэкенда (убивает :9090, стартует отсоединённо, ждёт порт) | После правок кода/патчей venv |
| `launch\run-tunnel-design.bat` | Только окно туннеля | Переустановить туннель при живом бэкенде |
| `launch\start_devbim.bat` | Бэкенд в окне консоли (лог в консоль) | Отладка бэкенда глазами |

Служебные (руками не запускать): `launch\_restart_server.ps1` — перезапуск
отсоединённо через WMI (им пользуются агенты и `start_server.bat`);
`launch\_ir_server_hidden.bat` — скрытый старт, пишет `ir_server.log` в корне.

Типовая диагностика: `status-design.bat` → если `backend DOWN` —
`start-system-design.bat`; если туннель есть, а сайт 502 — подождать ~5 с
(первый запрос после старта туннеля бывает холодным) и повторить статус.

- цвета бренда: жёлтый `#E6FD13` → голубой `#38BDF8`; логотипы/фавиконы
  перегенерируются двухцветными (Dev — `#111111`, BIM — `#38BDF8`);
- брендовый **баннер над интерфейсом** (`devbim_banner.js` →
  `dist/devbim-banner.js` + тег `<script>` в `index.html`): тёмная полоса
  44px поверх всего приложения — кликабельный логотип DevBIM (ведёт на

## Style-пресеты (промты по умолчанию)

Стоковые шаблоны InvokeAI (Photography, Anime, …) заменены набором для трёх
сценариев выпуска альбомов проектной документации. Пресет дополняет промпт
пользователя (подставляется вместо `{prompt}`) профессиональной
архвиз-обвязкой: камера, свет, материалы, окружение, качество. Названия и
тексты — на английском (русскоязычная адаптация интерфейса запланирована
отдельно; когда появится — переименовать `PRESETS` и превью). Свой промпт
пользователь пишет на любом языке. Скриншот: `docs/style-presets-ui-en.png`.

- **Facades** (4): Neutral Daylight · Golden Hour · Blue Hour (Evening) ·
  Frontal (Album Sheet — вид «в упор», без перспективы)
- **Interiors** (3): Daylight · Evening Light · Public Space
- **Master Plan** (3): Aerial (Top-Down, надир) · Bird's Eye (45°) ·
  Orthographic (Album Sheet — плоский вид, без теней и перспективы)

У каждого пресета есть превью-картинка (256 px, генерируется через
ImageRouter по демо-сюжету): сначала `make_style_previews.py` кладёт PNG
в `style_preset_images/` (имя файла = имя пресета), затем setup-скрипт
копирует их в пакет — для default-пресетов InvokeAI ищет превью **по имени
пресета** в `default_style_preset_images/`. Поэтому имена пресетов обязаны
быть корректными именами файлов Windows (без `/ \ : * ? " < > |` — было
наступлено на «(3/4)»); при переименовании пресетов setup сам вычищает из
пакета устаревшие PNG. Перегенерация одного/всех:
`make_style_previews.py [--only-missing]`; основная модель — платная
`Tongyi-MAI/Z-Image-Turbo` (~0.0016 кредита/картинка; у `:free`-моделей
лимит 3 запроса/сутки исчерпывается мгновенно).

InvokeAI при каждом старте удаляет пресеты `type='default'` и заново сеет
их из `venv/.../style_preset_records/default_style_presets.json`, поэтому
правки только в БД живут до перезапуска. Скрипт правит и seed-файл, и живую
БД — работающий сервер подхватывает без перезапуска (в UI — F5). Оригинал
сохранён рядом как `default_style_presets.json.orig`.

```powershell
.\venv\Scripts\python.exe setup_style_presets.py            # применить
.\venv\Scripts\python.exe setup_style_presets.py --restore  # вернуть стоковые
.\venv\Scripts\python.exe tests\test_style_presets.py       # проверка
```

Пресеты правятся в списке `PRESETS` в `setup_style_presets.py`; seed-файл
пишется ASCII-эскейпами (`ensure_ascii`): InvokeAI читает его `open()` без
encoding, и без этого кириллица названий падает на cp1251 вне PYTHONUTF8=1.

## ImageRouter

Интеграция облачных моделей через [ImageRouter](https://docs.imagerouter.io/)
(OpenAI-совместимый шлюз: FLUX, GPT-Image, Nano Banana, Qwen-Image и др.).
Скриншоты: `docs/imagerouter-tab.png`, `docs/imagerouter-canvas.png`.

### Секреты: `.env` (ключ и админский пароль)

Секреты живут в `.env` в корне проекта и подтягиваются сервером при каждом
запуске (в браузер не отдаются; в git не входит):

| Переменная | Назначение |
|---|---|
| `IMAGEROUTER_API_KEY` | ключ ImageRouter; имеет приоритет над ключом, введённым через UI (`data/imagerouter.json`). Смена: поправить строку и перезапустить сервер |
| `ADMIN_PASSWORD` | админский пароль для входа в «Менеджер моделей» (см. следующий раздел) |

Если `.env` нет, `setup_imagerouter.py` создаёт шаблон (ключ переносится из
`data/imagerouter.json`, пароль — `change-me`). Проверка, что ключ подтянулся:
`GET /api/v1/imagerouter/status` → `"key_source":"env"`.

### Админский пароль: «Менеджер моделей» за шестерёнкой

«Менеджер моделей» (управление ключом, каталог, генерация) по умолчанию
закрыт и перенесён в настройки (19.08.2026, вечер):

- вкладка «Модели» убрана из левой вертикальной рейки;
- вход — через кнопку «Меню» (внизу рейки): в группе «Настройки» появились
  пункт **«Менеджер моделей»** и штатная шестерёнка «Настройки»;
- клик по шестерёнке «Настройки» или по пункту «Менеджер моделей» открывает
  **модальное окно ввода пароля** (скриншот: `docs/admin-password-modal.png`);
  пароль сверяется на сервере с `ADMIN_PASSWORD` из `.env`;
- после верного пароля открываются сами настройки / «Менеджер моделей»;
  разблокировка действует до перезагрузки страницы (F5 — снова пароль);
- обходные пути тоже закрыты: кнопка «Manage Models» в выпадающем списке
  моделей, горячие клавиши и прочие переходы на вкладку моделей перехватываются
  тем же окном пароля; восстановление вкладки «Модели» после перезагрузки
  возвращает на «Generate».

Если `ADMIN_PASSWORD` в `.env` пуст/отсутствует — защита отключена,
пароль не запрашивается (`GET /api/v1/imagerouter/admin-auth` → `protected`).

### Где модели ImageRouter в интерфейсе

- **Левая панель — только параметры API (19.08, вечер)**. Поскольку система
  работает только через API ImageRouter, из левой панели Generate и Canvas
  скрыты параметры, настраивающие исключительно локальные модели: аккордеоны
  «Refiner» и «Advanced» (VAE, VAE Precision, CFG Rescale, Seamless X/Y),
  «Compositing» (Coherence/Infill) на канвасе, блок «Concepts» (LoRA) и
  сворачиваемые «Advanced Options» с Scheduler/Steps/CFG Scale. Осталось
  только то, что реально уходит в API: промпт (+Reference Image), модель,
  размер (Aspect/Width/Height → `size`), seed. «Advanced Options» внутри
  аккордеона «Image» на канвасе оставлен — это масштабирование кадра
  (Scale Before Processing), оно определяет кроп/размер исходника для правки.
  Патч применяется функцией `patch_left_panel()` в `setup_imagerouter.py`.
- **Меню добавления слоёв канваса — без Control Layer (05.09)**. Пункт
  «Слой управления» (ControlNet) убран из меню «+» панели Control Layers:
  ControlNet-модели работают только с локальной генерацией, которой нет.
  Остаются Inpaint Mask, Regional Guidance, Regional Reference и растровый
  слой — всё, что уходит в облачный edits-запрос. Существующие control-слои
  в сохранённых канвасах продолжают отображаться (удаляются вручную).
  Функция `patch_canvas_control_layer()` в `setup_imagerouter.py`.
  Вкладка Upscaling не тронута — планируется модернизация под облако.
- **Левая вертикальная рейка вкладок (19.08, вечер)** — скрыты: вкладка
  «Очередь» (статус генерации и так виден у кнопки Generate), колокольчик
  уведомлений (в его поповере показывается «Что нового в DevBIM» —
  обновления локальной сборки не актуальны; всплывающие тосты об ошибках
  остаются) и кнопка Support Videos. Функция `patch_left_rail()` в
  `setup_imagerouter.py`.
- **Canvas / Generate (основной экран генерации)** — модели ImageRouter
  появляются прямо в выборе модели рядом с локальными; генерация с ними
  выполняется через API ImageRouter, результат сохраняется в галерею как
  обычное изображение (штатные события `invocation_complete` и т.д.).
  Промпт и размер берутся из графа; «число итераций» = количество картинок
  (не более 10 за раз). Параметры steps/cfg/scheduler облачными моделями
  игнорируются — у API есть только size/quality. Во время генерации видна
  строка прогресса («модель · i/N · секунды») и счётчик очереди — облачный
  запрос отображается в UI как обычная генерация.
- **Редактирование (inpaint/outpaint/img2img)** — если на канвасе есть
  исходное изображение, запрос уходит в `/v1/openai/images/edits`:
  передаются промпт и исходное изображение. Маска слоя Inpaint Mask
  учитывается так: зона правки подсвечивается прямо в картинке (шлюз
  ImageRouter не принимает параметр маски ни у одной модели), а результат
  вклеивается **только внутрь выделенной зоны** — всё остальное изображение
  остаётся пиксельно исходным. Требуется модель с пометкой «редактирование»
  в описании (например `google/nano-banana-2`, `qwen/qwen-image-edit`,
  `openai/gpt-image-2`, `black-forest-labs/flux-kontext-*`);
  для остальных вернётся понятная ошибка. Промпт описывает, что сделать
  с выделенной зоной («удали балкон», «поставь кондиционер»).
- **Референсные изображения (Reference Image)** — добавьте на канвас
  референс и выберите в его панели модель **ImageRouter (референс)**
  (без выбранной модели клиент игнорирует референс и показывает «!»).
  Референсные картинки передаются в API как дополнительные входные
  изображения (`image[]`) вместе с промптом; работает и вместе с правкой
  (подложка + маска + референсы), и без подложки. Требуется модель
  с пометкой «редактирование».
- **Model Manager — за админским паролем (19.08.2026, вечер)**: вкладка
  «Модели» убрана из левой рейки; вход через «Меню» → группа «Настройки» →
  пункт **«Менеджер моделей»** (или шестерёнка «Настройки») с вводом пароля
  из `.env` (`ADMIN_PASSWORD`). Внутри — вкладка **ImageRouter**: ввод/проверка
  ключа, каталог моделей (поиск, фильтр «только бесплатные», сортировка, цены)
  и форма генерации с просмотром результата. Вкладки установки локальных
  моделей (Launchpad, URL/путь, HuggingFace, скан папки, стартовые модели)
  скрыты.

Технически: модели помечаются ключами `imagerouter/<provider>/<model>` и
показываются как main-модели (base sdxl — только чтобы граф собрался;
локально ничего не исполняется). Запрос `enqueue_batch` с такой моделью
перехватывает мидлварь `ImageRouterCanvasMiddleware`: вызывает
`/v1/openai/images/generations`, сохраняет картинку через сервис галереи и
отправляет клиенту события как при обычной генерации. Удаление такой
«модели» из списка заблокировано (это каталог API, а не файлы).

Главная кнопка генерации переименована из «DevBIM» в понятную
**«Generate»** (левая панель, рядом со счётчиком итераций; также
Ctrl+Enter и «Add to Queue» на панели канваса). Подсказки интерфейса,
упоминавшие нажатие кнопки, обновлены.

API бэкенда (Swagger: `/docs`): `GET /api/v1/imagerouter/status`,
`PUT|DELETE /api/v1/imagerouter/key`, `GET /api/v1/imagerouter/credits`,
`GET /api/v1/imagerouter/models`, `POST /api/v1/imagerouter/generate`,
`GET|POST /api/v1/imagerouter/admin-auth` (статус защиты / проверка пароля).

### «Вырезать по контуру» (✂) на холсте

Кнопка-ножницы ✂ внизу вертикальной рейки инструментов холста. Поток:
клик по ✂ → кликами по канвасу ставятся точки замкнутой полилинии
(превью: рёбра, резиновая линия к курсору, полупрозрачная заливка; ПКМ
убирает последнюю точку, клик у первой точки замыкает контур) →
**Ctrl+C / Enter / ✓ «Подтвердить»** — кусок картинки по контуру
копируется **новым растровым слоем поверх текущего**: подложка остаётся с
оригинальным изображением (дырки нет), слой-кусок не выделяется (нет
рамки-обводки) — «Двигать (V)» всё равно тащит его по клику. **Esc / ✕
«Отменить»** — выход без изменений. **Ctrl+V** — вставить копию
последнего вырезанного кусочка (ещё один новый слой, со сдвигом +24 px,
чтобы повторные вставки были видны). Зум во время рисования работает
(колесо не перехватывается).

Источник вырезания — выделенный растровый слой (если выделено не
растровое — верхний растровый слой с содержимым). Undo: 2 шага Ctrl+Z
на каждое вырезание/вставку. Пока ножницы активны, остальные кнопки
инструментов выглядят неактивными (клик по любому из них завершает
режим ножниц).

Перетаскивание кусочков — плавное, без привязки к сетке (у остальных
слоёв остаётся штатный «snap to grid» 64 px; при зажатом Ctrl шаг
мельче — 8 px). Плавность сохраняется и после перезагрузки страницы.

### Диагностика

- Тост «Не удалось поставить пакет в очередь» показывает текст ошибки
  ImageRouter (нет ключа, модель без правки, сбой облака). Если вместо
  текста «Неизвестная ошибка» — смотрите `ir_server.log` и дамп графа
  `data/_ir_last_graph.json`.
- При каждом перехвате генерации граф сохраняется в
  `data/_ir_last_graph.json` — по нему видно, что реально ушло с канваса
  (модель, промпт, картинка, маска).
- «Картинка из вьювера не ушла, генерация только по промту» — сначала
  проверьте дамп `data/_ir_last_graph.json`: если узлов `ip_adapter`
  с `image_name` в нём нет, картинка не приложилась на клиенте. Самая
  частая причина — вкладка браузера открыта со старой версией интерфейса
  (до последнего обновления сервера): обновите страницу (F5 / Ctrl+F5).
  Если `ip_adapter` в дампе есть, а результат «не похож» на референс —
  возможно, референс слишком тёмный/пустой (например, почти чёрная
  «ночная» картинка): модели нечего в нём сохранять.
- После каждого обновления сервера (setup-скрипты + перезапуск)
  обязательно обновляйте страницу в браузере — старая вкладка работает
  на прежнем JS и новые исправления не применяет.
- «API-ключ не задан» — задать `IMAGEROUTER_API_KEY` в `.env` и перезапустить
  сервер (или ввести ключ на вкладке ImageRouter — сохранится в
  `data/imagerouter.json`; значение из `.env` имеет приоритет).
- «Неверный пароль» в окне администратора — пароль задаётся `ADMIN_PASSWORD`
  в `.env`; после правки перезапустить сервер. Забыли пароль — откройте `.env`.
- Окно пароля не появляется — защита отключена (`ADMIN_PASSWORD` пуст или
  нет `.env`): `GET /api/v1/imagerouter/admin-auth` → `{"protected":false}`.
- «Модель не поддерживает редактирование» — выбрана text-to-image модель,
  для правки фото нужна модель с пометкой «редактирование».
- «Не удалось загрузить исходное изображение» — канвас ссылается на
  удалённую картинку (например, после чистки галереи); заново положите
  изображение на канвас.
- Порт 9090 занят другим процессом — проверьте, что не запущено два
  сервера (`netstat -ano | findstr :9090`), лишний завершите.

### Апскейлинг (вкладка «Увеличение»)

Вкладка **Upscaling** работает целиком через ImageRouter — локальные
ESRGAN/ControlNet-модели не нужны. Пользователь загружает картинку (или
жмёт «Send To Upscale»/«Постобработка (Shift+U)» над изображением галереи),
выбирает **Upscale Model**, масштаб (2/4/8) и опционально Creativity/
Structure — запрос уходит в `/v1/openai/images/edits` с серверным промптом
(«увеличь ~Nx, сохрани композицию и содержание»), результат появляется в
галерее с метаданными `generation_mode: imagerouter-upscale`.

- **Список моделей для пользователей выбирает администратор**: Меню →
  Настройки → пароль → «Менеджер моделей» → колонка «Апскейлинг»
  (чекбоксы; **первая модель списка — по умолчанию**, порядок меняется
  стрелками ↑↓; поиск — только модели со входом-image). Выбор хранится в
  `data/imagerouter_upscale.json` (per-company); без файла используется
  список по умолчанию: clarity-2x, swinir-2x, latent-2x, P-Image-Upscale,
  ccsr-2x (все проверены живыми запросами, ~$0.004–0.009/картинка).
  После сохранения пользователям нужно обновить страницу (F5).
- Служебные fake-модели (видны только внутри системы): выбранные модели
  инъектируются как `spandrel_image_to_image` с ключами
  `imagerouter-upscale/...`, плюс декоративный `Tile ControlNet
  (ImageRouter)` (base sdxl) — вкладка требует его наличия, исполняется
  всё равно облако.
- Слайдеры Creativity/Structure переводятся в пояснения промпта
  (пороги), Tile Size/Tile Overlap игнорируются. Блок
  «Creativity & Structure Defaults» (пресеты Conservative/Balanced/
  Creative/Artistic + подсказки про промт) удалён с лончпада вкладки —
  это управление локальной tiled-диффузией (`patch_upscale_launchpad`
  в setup_imagerouter.py).
- **ГРАБЛЯ (фактический размер)**: модели апскейлят по-своему, запрошенный
  размер — лишь пожелание: clarity-2x/swinir-2x/latent-2x/ccsr-2x дают
  ровно ×2 от входа (запрос 4x вернёт 2x), P-Image-Upscale — 2048²/2896².
  Для повторного увеличения прогоните результат ещё раз.
- Быстрый «Постобработка (Shift+U)» из контекстного меню картинки — тот же
  путь (adhoc-граф, масштаб ×2).

## IFC-вьювер (BIM)

Отдельная вкладка **«IFC»** в левой рейке (после «Рабочие процессы») —
3D-просмотрщик BIM-моделей в формате IFC. Геометрия разбирается прямо в
браузере (web-ifc WASM + @thatopen/components, всё локально, без CDN);
сервер только хранит файлы. Скриншот: `docs/ifcviewer-tab.png`.

Возможности:

- открытие IFC с диска («Открыть файл…») или из списка моделей на сервере
  (загружаются через API, хранятся в `data/ifc/`);
- орбитальная камера: ЛКМ — вращение, колесо — зум, ПКМ — панорама;
- дерево здания: проект → площадка → здание → этажи → элементы;
- клик по элементу (в 3D или дереве) — подсветка + свойства: атрибуты
  и наборы свойств (psets) с количеством;
- «Скрыть» / «Изолировать» / «Показать всё» для выделенных элементов
  (в дереве скрытые показываются тусклыми);
- **улучшения снимков для ИИ-рендеринга** (06.09, ночь):
  - **контактная тень** — в каждый снимок под пятном здания
    автоматически добавляется мягкая тень (видна только в прозрачных
    полях) — генерация «ставит» здание на землю, а не вешает в воздух;
  - **BIM-контекст промта** — по позиции человека (или выделенному
    элементу) строится строка вида `BIM context: floor "Nivel 1",
    element SLAB` (этаж/помещение/класс элемента из модели); при
    «📸 To Canvas»/«💾 To Assets» она копируется в буфер обмена —
    вставьте её в промт (Ctrl+V); поле также видно в панели «Человек»;
  - **панель «📷 ▾» (Камера)**: ползунок **FOV 20–90°** (телеобъектив —
    строгие фасады, широкий — интерьеры); **«⌷ Вертикали»** — в виде
    от глаз убрать наклон камеры, вертикали стен строго вертикальны
    (двухточечная перспектива, горячая **V**); **«— Горизонт»** —
    выровнять орбитальную камеру; **«▦ Орто-фасад»** — строгий
    фронтальный ортографический вид по нормали выбранного элемента
    (кликните по стене) — идеальные исходники фасадов; **рамка кадра**
    1:1 / 3:2 / 16:9 / … — снимок кадрируется по рамке (стороны
    по-прежнему кратны 64);
- **«Человек»** — силуэт для масштаба + камера от глаз (как Position
  Camera / Walk в SketchUp), панель «👤 ▾» в тулбаре:
  - «Поставить на перекрытие» — режим постановки, следующий клик по
    модели ставит фигуру (1,75 м, поворачивается лицом к камере);
    привязка автоматическая: вертикальный луч вниз находит поверхность —
    клик по перекрытию/полу/крыше ставит на неё, клик по стене опускает
    на пол под ней; под точкой нет геометрии (двор без плиты) —
    остаётся высота клика;
  - «👁 Вид от глаз · 1,7 м» — камера в глаза фигуры: перетаскивание
    мышью — осмотр, WASD/стрелки — ходьба (Shift — быстрее), при
    ходьбе человек следует за камерой и перепривязывается к полу;
    ESC или кнопка — возврат к прежнему виду орбиты;
  - при загрузке другой модели человек убирается автоматически;
- секущие плоскости — панель «Сечения ▾» в тулбаре вьюпорта (06.09):
  - три типа сечений: **горизонтальное** (план, срезается верх) и
    **вертикальные X / Z** (разрез вдоль/поперёк; срезается половина,
    обращённая к камере);
  - тумблер **«👁 Плоскости»** скрывает/показывает вспомогательные
    плоскости — само сечение продолжает действовать (для чистых снимков);
  - список активных сечений: у каждого **слайдер** позиции вдоль оси
    (координата в метрах), **⇄ разворот** стороны отсечения, **👁 скрытие**
    конкретной плоскости и **✕ удаление**; «Удалить все» внизу;
  - плоскость также тянется мышью за стрелку (перетаскивание стрелки
    обновляет слайдер); сечения переживают загрузку другой модели;
- водяной знак движка @thatopen отключён (`showLogo = false`), вместо
  него в левом нижнем углу вьюпорта — знак «DevBIM — Design»
  (не перехватывает клики, виден и в embed-режиме на «Холсте»).

### Панель «IFC Viewer» на вкладке «Холст» (снимок модели → генерация)

Вкладка **«Холст»**, главная область: рядом с «Image Viewer» есть панель
**«IFC Viewer»** — тот же вьювер без боковых панелей (шапки, дерева,
свойств). Внизу плавающая панель: селектор моделей с сервера и кнопки
**«📸 To Canvas»** и **«💾 To Assets»** (как в PDF-вьювере). Скриншоты:
`docs/ifcviewer-canvas-panel.png`, `docs/ifcviewer-canvas-underlay.png`.

Те же кнопки «📸 To Canvas» / «💾 To Assets» с 11.09 видны ВНИЗУ и в
полноценной вкладке «IFC» (без селектора моделей — он в шапке): снимок
текущего вида можно отправить на холст или в ассеты прямо из вкладки.

Как это работает:

- снимок делается на **прозрачном фоне** (альфа-канал): WebGL-рендерер
  создаётся с `alpha:true`, фон сцены `null` — здание без окружения,
  стороны кратны 64 (требование ImageRouter), поля вокруг вида прозрачные;
- «📸 To Canvas» загружает снимок в галерею и кладёт на холст
  **базовым растровым слоем-подложкой** (холст очищается, рамка подгоняется
  под снимок; вместе со снимком создаётся выделенный слой «Маска
  перерисовки» и включается кисть); приложение переключается на рабочую
  область холста; генерация запускается штатной кнопкой Generate;
- «💾 To Assets» сохраняет снимок во вкладку **«Assets»** галереи
  (`image_category=user`), не трогая холст;
- для правки снимка выбирайте **модель правки**: `google/nano-banana:free`,
  `openai/gpt-image-2:free`, `openai/gpt-image-2`, `qwen/qwen-image`,
  `black-forest-labs/flux-kontext-dev`. Обычные генеративные модели
  (например, `illustrious-xl`) вход-картинку не редактируют — посредник
  обнаружит «эхо» (модель вернула вход без изменений) и выдаст понятную
  ошибку вместо фейкового результата. У `:free`-моделей лимит
  3 запроса в сутки;
- **маску рисовать не обязательно**: без маски правится вся картинка —
  снимок уходит модели **с альфа-каналом (без фона)**: модель получает
  здание без окружения и дорисовывает его сама по промпту («добавь
  окружение»). Непрозрачные исходники (фото, фрагменты PDF) не меняются —
  у них прозрачности нет. Если нужна локальная правка — нарисуйте «Маску
  перерисовки» (слой маски + кисть), тогда изменится только выделенная
  зона. Кнопка Generate блокируется, если на холсте есть слой
  «Региональная точность» без промпта — удалите его или впишите промпт;
- модель в панель подгружается автоматически: берётся последняя модель,
  открытая на вкладке «IFC» (синхронизация через localStorage, включая
  живую подмену при переключении); локальные файлы с диска не
  синхронизируются — используйте селектор в панели;
- панель неактивна — вьюпорт выгружается (модель при возврате
  перезагрузится автоматически, положение камеры сбросится).

Технически: iframe `/ifcviewer.html?embed=1`; снимок — форс-рендер +
`toDataURL` (WebGL-буфер живёт только в кадре рендера); мост
`window.__devbimIfc.toCanvas(imageDTO, generate)` в App-бандле (патч
`setup_ifcviewer.py`) переиспользует механизм «Send to Canvas» и запуск
генерации холста. Детали и грабли — HANDOFF.md, п. 13, 20.

API бэкенда (Swagger: `/docs`): `GET /api/v1/ifc/list`,
`POST /api/v1/ifc/upload` (multipart `file`, до 500 МБ, только
`.ifc`/`.ifczip`/`.ifcxml`), `GET|DELETE /api/v1/ifc/file/{name}`.
Имена проверяются — пути (`../`) не проходят.

## PDF-вьювер

Отдельная вкладка **«PDF»** в левой рейке (после «IFC») — просмотр

отдельно). Возможности:

- открытие PDF с диска («Open File…») или из списка документов на
  сервере (select в шапке); кнопка «⬆ Upload» сохраняет открытый с

- **рамка фрагмента**: ЛКМ-перетаскивание по странице (вне рамки область
  затемняется), новая рамка заменяет прежнюю, ESC или клик — сброс;
- **«🖼 To Canvas»** — фрагмент загружается в галерею и кладётся на холст

- качество: фрагмент рендерится заново в высоком разрешении (целевая
  длинная сторона 2048 px, лимит полной страницы 16 Мп, белый фон);
- автозагрузка: последний серверный документ и страница восстанавливаются

## 3D Design (генерация IFC по картинке)

Кнопка **«3D Design»** (фиолетовая, в ряду Generate левой панели) строит
упрощённую объёмную BIM-модель в формате IFC по картинке. Сценарии:
**«Генплан»** (фаза 1), **«Фасад»** (фаза 2), **«Интерьер»** (фаза 3) и
**«Сцена»** (фаза 4 — уличная сцена по фото с оценкой камеры).
Скриншоты: `docs/3d-design-modal.png`, `docs/3d-design-ifc-result.png`,
`docs/3d-design-facade-{modal,result}.png`,
`docs/3d-design-interior-{modal,result}.png`,
`docs/3d-design-scene-{modal,plan,view}.png`,
`docs/3d-facade-default-view.png`.

Поток:

1. нажмите «3D Design» — откроется модалка: плитка сценария «Генплан»,
   превью картинки-источника и поле уточнений;
2. источник — картинка с **Холста** (если на нём есть контент) или
   выбранная в **галерее/вьювере**; нет ни того, ни другого — модалка
   подскажет «положите картинку на Холст или выберите в галерее»;
3. в поле уточнений задайте, что модель должна учесть обязательно:
   этажность и назначение корпусов, масштаб («жилой 5 этажей, школа 3,
   масштаб 0.5 м/px»); без уточнений модель оценит всё сама;
4. «Сгенерировать 3D» — ИИ-модель анализирует картинку, обводит здания
   и строит модель: корпуса по этажности, школа/детсад, земля, дороги,
   парковки и площадки; допущения (масштаб, выброшенные контуры)
   показываются тостом. Генерация идёт **в фоне** (конвейер с
   самопроверкой занимает 1–6 мин): модалка показывает таймер и этап —
   «Анализ картинки (VLM)» → «Сборка IFC-модели» → «Самопроверка VLM»;
   модалку можно закрыть — по готовности приложение само откроет вкладку
   IFC и покажет тост. Одна генерация одновременно, вторая ждёт
   («В очереди»);
5. готовая модель автоматически открывается во вкладке **«IFC»** —
   орбитальная камера, дерево, свойства каждого объёма (этажность,
   площади, объёмы, отметка «приближённая геометрия»), сечения и
   «Человек» для масштаба, как у обычных IFC-моделей.

Дальше — штатный цикл визуализации: поставьте человека, выберите
ракурс, «📸 To Canvas» → ИИ-рендер окружения (см. IFC-вьювер).

Модель-аналитик (какая ИИ-модель разбирает картинку) выбирается
администратором: Менеджер моделей (шестерёнка) → «3D-генерация — модель
аналитики»; по умолчанию `openai/gpt-6-astra` (список — только модели,
принимающие картинку и отвечающие текстом). Стоимость: фактические
токены каждого VLM-запроса считаются по тарифам каталога ImageRouter и
показываются тостом «потрачено $X» после генерации; детализация
(вызовы/токены/цена) — ключ `usage` в дампе `data/ifc/_threed_last.json`.
Для экономии модель можно переключать (astra точнее всего, `gpt-6-sol`
в 5 раз дешевле, `gpt-6-luna` — в 100). Файлы моделей и
диагностический дамп последней генерации — `data/ifc/` (модели
`3D_plan_*.ifc`, обводка-превью `*_preview.png` рядом).

> Модель концептуальная: обводка кровель по растровой схеме, размеры и
> этажность оценочные, без геопривязки — не использовать как обмерную
> или рабочую документацию.

### Сценарий «Фасад» (фаза 2)

Вход — фото, рендер или чертёж фасада (с размерными линиями или без:
масштаб ИИ оценит по опорам — этаж ~3 м, окно ~1.5×1.5 м, дверь ~2.1 м,
балкон ~3×1.2 м). Выберите плитку «Фасад» в модалке (placeholder подскажет

Результат — концептуальный объём: поэтажные тома, сетка окон (с
пропусками), балконы-плиты со 2 этажа, цоколь, плоская или двускатная
крыша, цвета по картинке; рядом — чертёж-превью в метрах. Допущения
(перспектива принята за орто, глубина по умолчанию 12 м) пишутся в
свойства FacadeModel и показываются тостом. Окна/балконы выбираются в

> Как и генплан — концепт по картинке, не обмерная документация.

### Сценарий «Интерьер» (фаза 3)

Вход — 2D-план квартиры или помещения (чертёж, фрагмент PDF, скрин),

подскажет формат уточнений («высота стен 2.8, масштаб 0.01 м/px, стены
по чертежу»); масштаб ИИ оценит по опорам (дверной проём 0,9–1 м,
кровать 2×1,6 м, унитаз 0,4 м) или по размерной линии, если она есть.

Результат — концептуальная «квартира с блоками» во вкладке IFC: плита
пола, стены-сегменты с толщиной с плана, тёмные проёмы (двери/окна)
сквозь стены, комнаты IfcSpace с именами, прочитанными с плана
(«Кухня», «Спальня» — видно при выборе в дереве вьювера), мебель
IfcFurnishingElement с типом и цветом (кровать, диван, стол, …),
рядом — чертёж-превью плана в метрах. Дальше — штатный цикл визуализации
интерьера: поставить человека, «Вид от глаз», развернуть камеру →
«📸 To Canvas» → снимок + реальные фото предметов как Reference Images +
промт («стены покрась…») → генерация интерьера именно с того ракурса и
с теми предметами.

Файлы: `data/ifc/3D_interior_*.ifc` + `*_preview.png`.

> Концепт по обводке плана, не обмерная документация; фотореалистичность
> даёт второй этап (снимок + референсы + ИИ-правка), а не 3D-модель.

### Сценарий «Сцена» (фаза 4)

Вход — **фото улицы/двора** (1–3 здания, деревья, машины, люди). Плитка
«🌇 Сцена» в модалке; placeholder подскажет формат уточнений («2 дома:
главный 7 этажей, второй 3 справа; деревья вдоль дороги; камера слева»).
ИИ оценивает и геометрию, и **положение камеры фото** (азимут к фасаду
±75°, высота глаз, дистанция).

Результат — грубая уличная сцена из примитивов: здания (тома-этажи,
окна на фронте и боковинах главного, балконы, цоколи, крыши), деревья
(ствол+крона), машины, люди, земля-плита; рядом — план-превью с маркером
камеры и направлением съёмки. **Камера вьювера после генерации встаёт как
на фото** (фронтально-сбоку, уровень глаза) — это заготовка для «здания
под новым углом» в ИИ-рендере. Подсказка камеры одноразовая: повторная
загрузка модели возвращает обычный «вписать». Параметры камеры продублированы
в свойствах проекта (pset CameraHint — азимут/высота/дистанция).

Файлы: `data/ifc/3D_scene_*.ifc` + `*_preview.png` (план сцены).

> Как и остальные сценарии — концепт по фото (перспектива принята за
> ортогональную), не обмерная документация.

### Двухканальный ансамбль геометрии (26.09)

В темах «Генплан», «Фасад» и «Интерьер» геометрия извлекается двумя
независимыми прогонами и сводится детерминированным кодом («VLM выбирает
семантику, код считает геометрию»): прогон A — параметрический JSON
моделью-аналитиком; прогон B — grounding-боксы в пикселях отдельной
моделью (`openai/gpt-6-sol`, победитель live-зонда). Согласованные числа
усредняются, спорные поля разрешает один реферти-вызов, затем следует
регуляризация (снапы, симметрия сетки окон, ортогонализация контуров) по
гейту согласия. Судья самопроверки получает не только исходную картинку,
но и оверлей геометрии поверх неё.

- Итог live A/B (серии ×3): фасад 38 → 43 и генплан 90 → 96 — строго
  лучше baseline; интерьер 96 = 96 (потолок судьи на синтетике).
  Структурные проверки 100%, стоимость ≤ 1.8× baseline.
- Сбой любой части ансамбля — warning в лог и работа с прогоном A
  (качество как до ансамбля). Полное выключение — `THREED_ENSEMBLE=0`.
- Переменные `.env`: `THREED_ENSEMBLE` (по умолчанию 1),
  `THREED_ENSEMBLE_MODEL` (модель прогона B), `THREED_REFEREE_MODEL`
  (судья споров, по умолчанию sol), `THREED_MAX_CALLS_PER_ATTEMPT`
  (бюджет VLM-вызовов на попытку, по умолчанию 6).
- Диагностика: pset **EnsembleAgreement** у модели в DevBIM; ключ
  `ensemble` в дампе `data/ifc/_threed_last.json` (mode, b_model,
  agree_rate, disputed, referee).

## Многопользовательский режим (devbim.com)

Студия как сервис в кабинете сайта devbim.com: пользователь сайта входит в
студию без второго логина (сайт обменивает свой JWT на сессию студии),
роли `admin`/`user`, личные воркспейсы (картинки, борды, очереди, IFC/PDF/3D
изолированы по владельцу). Режим переключается ключом в `.env` — мидлварь
входа разворачивается тем же `setup_site_auth.py` (идемпотентен).

| Переменная | Назначение |
|---|---|
| `STUDIO_AUTH_MODE` | `password` (по умолчанию — локальные компании, прежнее поведение) или `sso` (devbim.com) |
| `STUDIO_JWT_SECRET` | общий секрет с бэкендом devbim.com (HS256, ≥32 символов) |
| `STUDIO_SESSION_SECRET` | секрет куки сессии (опц.; по умолчанию — `STUDIO_JWT_SECRET`) |
| `STUDIO_SESSION_TTL` | срок сессии в секундах (опц.; по умолчанию 43200 = 12 ч) |
| `STUDIO_FRAME_ANCESTORS` | CSP `frame-ancestors` (опц.; по умолчанию `https://devbim.com http://localhost:* http://127.0.0.1:*`) |

Включение `sso`: сгенерировать секрет, вписать в `.env` студии и передать
разработчику сайта devbim.com вне канала (секрет общий, хранится с двух
сторон):

```powershell
python -c "import secrets;print(secrets.token_urlsafe(32))"
```

Вход: сайт открывает студию в iframe как
`https://studio.devbim.com/auth/sso?t=<JWT>` — требования к токену и
интеграции со стороны сайта — `docs/INTEGRATION-devbim-com.md`. Админ
дополнительно получает панель `/admin` (пользователи, смена роли,
блокировка) и вход по `SITE_PASSWORD` (`/auth/login`, фолбэк).

Локальная проверка без сайта — минт тестового JWT утилитой (секрет из
`.env` или `--secret`), открыть напечатанный URL в браузере:

```powershell
.\venv\Scripts\python.exe tools\mint_test_token.py --email a@b.io --role admin
```

Запуск на Linux-хостинге devbim.com — `launch/start_server.sh` (зеркало
`launch/start_devbim.bat`: `PYTHONUTF8=1`, `INVOKEAI_ROOT=<корень>/data`).

Тесты: `tests\test_studio_store.py`, `test_studio_auth.py`,
